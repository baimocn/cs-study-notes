# D9 候选池 — 备份还原与数据导入导出

来源：ch11《SQL Server 2012 安全管理》§11.4-11.6、§11.8、§11.9 及章末练习题 4-7。
性质：本单元是 D8 边界淘汰（verified.md X1/X2）的补位收编单元。
每条注出处小节。分类：框架 F / 原则规则 R / 案例 C / 反例 X / 术语 T。OCR 修复后表述。

## 一、框架类

- **F1. 备份与还原概念对偶**
  备份=制作数据库结构、对象和数据的复制，以便数据库遭破坏时修复；还原=将数据库备份加载到服务器中的过程。还原状态由备份决定；备份中未完成的事务不进行还原。〔§11.4.1〕
- **F2. 备份两大类、四类型体系**
  SQL Server 2012 把备份分为两大类：数据库备份、文件和文件组备份。数据库备份又分为三种：完整、差异、事务日志。合计四种备份类型。〔§11.4.2 开头〕
- **F3. 三种还原（恢复）模式**
  简单还原（Simple Recovery）、完全还原（Full Recovery）、批日志还原（Bulk-logged Recovery）。〔§11.4.3〕
- **F4. 备份还原操作链：设备→备份→还原**
  备份前先创建备份设备（存储数据库/事务日志/文件或文件组备份的存储介质，可为硬盘、磁带或管道）；可用 BACKUP DATABASE 语句或 SSMS 图形操作备份；还原用 SSMS"任务→还原→数据库"选源设备与备份集。四种备份类型在 SSMS 中执行相同步骤。〔§11.5.1、§11.5.2〕
- **F5. 导入导出工具定位**
  数据导入导出统一走 SSMS 的"导入和导出向导"（右键数据库→任务→导出数据/导入数据）：一次设定"源"与"目标"，复制表/视图数据或查询结果。〔§11.9〕

## 二、原则规则类

- **R1. 完整备份链前提**
  使用事务日志备份还原时，必须有一个完整的数据库备份；差异备份基于"最近一次数据库备份"。差异/日志备份都不能脱离完整备份独立还原。〔§11.4.2 之 2、3〕
- **R2. 还原顺序规则**
  综合方案还原顺序固定：先还原最近一次完整数据库备份→再还原最近一次差异备份→最后按顺序还原其后的各次事务日志备份。事务日志备份"还原时必须按一定的顺序进行"。〔§11.4.2 之 2、3〕
- **R3. 备份过程四不允许**
  SQL Server 2012 支持在线备份（一边备份一边其他操作），但备份过程中不允许：①创建或删除数据库文件；②创建索引；③执行非日志操作；④自动或手工缩小数据库或数据库文件。操作正在进行时备份被终止；备份中执行则操作失败、备份继续。〔§11.4.1〕
- **R4. 在线备份与断点续作**
  备份/还原过程中发生中断，可重新从中断点开始执行。〔§11.4.1〕
- **R5. 三种恢复模式与备份配置对应**
  简单还原：仅用数据库备份或差异备份，不涉及事务日志备份→只能还原到上一次备份的状态，无法还原到失败点；常用策略=数据库备份+差异备份。完全还原：数据库备份+事务日志备份→可还原到失败时刻，几乎不丢数据；策略=完整备份+差异备份+事务日志备份。批日志还原：备份策略与完全还原基本相同，尽量减少批操作日志空间。〔§11.4.3〕
- **R6. 文件/文件组备份的日志配套**
  文件或文件组备份不像完整备份那样同时进行事务日志备份；还原时要求有自上次备份以来的事务日志备份保证一致性——文件/文件组备份后应再进行事务日志备份，否则其中所有数据库变化无效。好处：只还原损坏的文件/文件组，还原速度快。〔§11.4.2 之 4〕
- **R7. 系统数据库备份清单**
  需定期备份 master、msdb、model 三个系统数据库（还原整个系统时重建系统用）；tempdb 不可能备份——每次启动实例时都重建，关闭时永久删除其中所有数据。〔§11.5.1 之 2〕
- **R8. 备份方案的决策三因素**
  选择备份类型由三因素决定：要求的还原能力（能否到失败点）、备份文件大小、留给备份的时间。只做完整备份→无法还原最近一次备份以来的事务（简单但丢失多）；完整+日志→可还原到失败点（未提交事务仍无法还原，失败后立即备份活动事务则可）。〔§11.6〕
- **R9. 导入数据结构一致要求**
  导入的数据来源表结构要与数据库中相应表结构一致；不一致须在"列映射"对话框详细设置，否则导入出错失败。〔§11.9 之 2〕
- **R10. 自动定时备份=维护计划，仅企业版**
  手工备份/还原之外，自动定时备份需用 SQL Server 2012 的维护计划功能；只有企业版提供，其他版本没有。〔§11.5.2 注意、§11.8〕
- **R11. 导入导出版本限制**
  教材断言：数据导出导入功能只在企业版或开发版才有，且必须安装至少 SP1 补丁后才能正常工作。〔§11.9 注意〕

## 三、案例类

- **C1. 综合备份方案（教材给的标准配方）**
  有规律完整备份（如每晚）→较短间隔差异备份（如 3~4 小时）→相邻差异备份之间事务日志备份（每 10 或 30 分钟）。〔§11.4.2 之 2〕
- **C2. 还原到失败点四步**
  ①若能访问事务日志文件，先备份当前活动的事务日志；②还原最近一次数据库备份；③还原最近一次差异备份；④按顺序还原差异备份以来的各次事务日志备份。若无法备份当前活动事务→只能还原到最后一次日志备份状态，而非失败点。〔§11.4.2 之 2〕
- **C3. 练习题 7：崩溃恢复应用题**
  每周五晚 12 点完全备份、每天晚 12 点差异备份、每小时日志备份，3 月 5 日（周三）4:50 崩溃。恢复：①（可能时）备份当前活动日志；②还原上周五晚的完全备份；③还原周二晚的差异备份（最近一次）；④按顺序还原周二午夜后至 4:00 的每小时日志备份；（必要时应用 4:00~4:50 的活动日志尾）使损失最小。〔练习题 7 + §11.4.2 方法〕
- **C4. §11.8 维护计划自动备份案例**
  student 库更新频率慢、数据量不大→选"数据库备份（完整）"策略，每周一次、周日晚 00:00 执行。维护计划向导：命名计划→新建作业计划（重复执行/每周/周日 0:00:00）→选维护任务"备份数据库（完整）"→选目标库与备份到磁盘→完成。生成形如 student_backup_年_月_日….bak 的文件。还原操作参考 11.5.2。〔§11.8〕
- **C5. §11.9 导出 student→Excel 案例**
  导出数据→向导选数据源（SQL Server Native Client 11.0 + 服务器 + student 库）→选目标（Microsoft Excel，D:\stu.xls）→选"复制一个或多个表或视图的数据"或"编写查询"→勾选源表（学生等）→可"编辑映射"调整列映射→执行成功（"已传输 10 行"）。〔§11.9 之 1〕

## 四、反例类

- **X1. 差异备份单独还原**
  只拿差异备份去还原——错。差异备份只含"最近一次完整备份以来的变化"，前提是存在完整备份；还原必须先还原完整备份再上差异。〔§11.4.2 之 2，R1 反推〕
- **X2. 事务日志备份单独恢复**
  只拿日志备份恢复——错。事务日志还原"必须有一个完整的数据库备份"，且各次日志须按备份顺序重放；跳序或无完整备份均失败。〔§11.4.2 之 3〕
- **X3. 备份 tempdb**
  tempdb 无法备份：实例启动即重建、关闭即清空，没有任何可备份的持久内容。〔§11.5.1 之 2〕
- **X4. 把"复制数据文件"当备份**
  备份≠复制文件：完整备份的过程是"先将事务日志写到磁盘上，再根据事务创建相同的数据库、对象并复制数据"，还原是把备份经还原过程加载回服务器、未完成事务不还原——直接拷 mdf/ldf 得到的是不一致快照，不能保证一致性还原。〔§11.4.1、§11.4.2 之 1 综合；后半句为标准语义补充，教材未明写〕
- **X5. 备份窗口内做禁操作**
  备份正在进行时创建索引/收缩数据库→操作失败、备份继续；操作正在进行时再启动备份→备份处理被终止。〔§11.4.1〕
- **X6. SSMS 逐击操作步骤**
  图 11-9~11-37 的界面逐击描述（备份设备窗口、备份对话框各选项、维护计划向导 8 步、导出向导 5 步截图）。〔§11.5、§11.8、§11.9 各图〕

## 五、术语类

- **T1. 备份设备**
  存储数据库、事务日志、文件或文件组备份的存储介质；可以是硬盘、磁带或管道；备份在硬盘中以文件方式存储；SQL Server 2012 只支持备份到本地磁带机（不支持网络远程磁带机）；备份设备是本地磁盘文件时其实不需要专门建立备份设备。〔§11.5.1 之 1〕
- **T2. 差异备份=增量备份**
  教材原话：差异备份"实际上是一种增量数据库备份"——只备份最近一次数据库备份以来的数据变化。〔§11.4.2 之 2〕
- **T3. 三种恢复模式英文名**
  Simple Recovery（简单还原）、Full Recovery（完全还原）、Bulk-logged Recovery（批日志还原，又称大容量日志恢复）。〔§11.4.3〕
- **T4. 导入和导出向导（DTS 血统）**
  SSMS 中右键数据库→任务→导入数据/导出数据，打开"导入和导出向导"；其技术前身即 DTS（数据转换服务），后演化为 SSIS。教材通篇只称"导入和导出向导"，未出现 DTS/SSIS 名称——DTS 定位一句：连接"源"与"目标"做表级数据搬运（可复制表或查询结果、可编辑列映射）的工具。〔§11.9；DTS/SSIS 血统为标准背景补充〕
- **T5. SSMS 备份类型选项与维护计划任务项**
  "备份数据库"窗口"备份类型(K)"下拉=完整/差异/事务日志；备份组件=数据库或文件和文件组；维护计划任务清单含"备份数据库（完整/差异/事务日志）"三项——与 F2 四类型体系互证（文件和文件组备份通过"备份组件"选，不计入类型下拉）。〔§11.5.1 图 11-12、§11.8 图 11-24〕
- **T6. 备份设备介质细节**
  NTFS 目录须给 SQL Server 系统用户读写权限否则报权限不够；未装磁带机时磁带不可选只能选文件。〔§11.5.1 图 11-10 注意〕
