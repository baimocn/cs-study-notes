# R 修炼心法（论断）

连接的本质：从两表的**广义笛卡儿积**中挑出满足连接条件的元组；交叉连接不挑（=笛卡儿积），内连接只留配上的，**外连接把没配上的也保留，缺的一侧填 NULL**。自然连接是等值连接再去掉重复列。ODBC 是**四层**体系：应用程序→驱动程序管理器→DBMS 驱动→数据源；应用程序**不能直接存取数据库**，管理器只负责加载调度，真正连库干活的是 DBMS 驱动。ADO 建立在 OLE DB 之上，ASP 中最重要的三成员是 connection、command、recordset。数据源（DSN）是连接的桥梁，**数据源不是数据库本身**。

# I 见龙在田（骨架 + 钩子）

## 钩子一：外连接一句话

> **内连接 = 只留配上的；外连接 = 保留没配上的，缺的那侧补 NULL。**

- LEFT JOIN：左表全保留，左表没配上的行→右侧全 NULL。
- RIGHT JOIN：右表全保留，右表没配上的行→左侧全 NULL。
- FULL JOIN：两边都没配上的也全保留。
- 方向只看 **JOIN 左边是谁**：`A LEFT JOIN B` 保留 A 的孤行；`A RIGHT JOIN B` 保留 B 的孤行。

## 钩子二：ODBC 四层 = 说话的 → 派活的 → 干活的 → 存货的

| 层 | 是谁 | 一句话职责 |
|---|---|---|
| 1 应用程序 | 用 VB/C++ 等写的程序 | 调 ODBC 函数、递交 SQL（说话的） |
| 2 驱动程序管理器 | 一个 DLL | 加载并调用正确的驱动、检查参数合法性、提供单一入口（**派活的**） |
| 3 DBMS 驱动程序 | 一个 DLL | 建立与数据源的连接、提交 SQL、转换数据格式、把错误转成 ODBC 标准错误码（**干活的**） |
| 4 数据源（DSN） | 一个命名，不是 DBS | 驱动与数据库连接的桥梁（存货的） |

判职责口诀：**看到"加载/调度/检查参数/单一入口"→管理器；看到"连接/提交SQL/格式转换/错误码转换"→驱动程序。**

## 钩子三：连接家族谱系（图 5-3）

```
θ连接（比较运算符任意）
 └─ 等值连接（θ 为 =）
     └─ 自然连接（再去掉重复属性列）
交叉连接 = 笛卡儿积 = 非限制连接（不带 ON）
```

等值连接 vs 自然连接（ch05 练习原题）：等值连接只从**行**的角度挑；自然连接还要**去掉重复列**，从行和列两个角度运算。

## 钩子四：ADO 链路与三成员

> 应用程序 → **ADO** → **OLE DB**（封装 ODBC，可连非 DBMS 数据源）→ 数据库

ASP 里最重要的三个 ADO 对象：**connection**（连接）、**command**（执行命令）、**recordset**（返回的记录集）。error=错误信息，field=recordset 的列。ADO 一般流程：连接 → 给命令 → 执行 → 处理结果集 → **关闭连接**。

# A1 书中例题（问题→用法→结论）

## 例1（ch05 例5.32/5.33 对照：外连接方向）

- 问题：学生表与成绩表连接，无成绩的学生要不要出现在结果里？
- 用法：`FROM 学生 LEFT OUTER JOIN 成绩 ON 学生.学号=成绩.学号` vs 换成 RIGHT。
- 结论：LEFT JOIN 以学生为主体，保留贾凌云、周红瑜、李晨、周春梅、张雪琪、李艾一共 **6 名**无成绩学生，其成绩列填 NULL；换成 RIGHT JOIN 这 6 人被舍弃，以成绩表为主体。**方向决定保留谁。**

## 例2（ch05 例5.2：笛卡儿积算账）

- 问题：学生表 4 行 5 列 × 专业表 3 行 3 列 = ？
- 结论：**4×3=16 行，5+3=8 列**。行相乘、列相加——所有 JOIN 行数题的地基。

## 例3（ch12 §12.1.1：ODBC 分层辨析）

- 问题：检查 ODBC 调用参数合法性、把 SQL 提交给数据源，各是谁的活？
- 结论：检查参数/加载驱动=驱动程序**管理器**；提交 SQL/连接数据源=DBMS**驱动程序**。两层都是 DLL，但职责不重叠。

## 例4（ch12 例5.31：自身连接）

- 问题：查至少给两个专业开课的教师。
- 用法：同一张"教师任课"表起两个别名 first/second，`ON first.教师编号=second.教师编号 AND first.专业代码!=second.专业代码`。
- 结论：自身连接**必须**给表取两个别名以示区别。

# A2 触发题型 ★

- **信号词"驱动程序管理器"** → ODBC 分层概念题：先背四层顺序（应用→管理器→驱动→数据源），再按口诀分职责。变体："驱动程序管理器是什么（DLL）/数据源是不是数据库（不是，是命名的桥梁）"。
- **信号词"LEFT JOIN…多少行"** → 行数计算题：先算配上的行数，再加保留侧没配上的行数（详见 E 区流程）。
- **信号词"等值连接与自然连接的区别"** → 差一个"去重复列"；"自然连接从行和列两个角度运算"。
- **信号词"ADO/ASP 访问数据库最重要的三个对象"** → connection、command、recordset。
- **信号词"ADO 是…的桥梁 / 构建于什么之上"** → 构建 于 OLE DB API 之上；连接 Web 应用程序和 OLE DB 的桥梁。
- **信号词"连接查询 / 多表查询"** → 先判类型：带 ON 等号=内连接（INNER 可省略）；带 LEFT/RIGHT/FULL=外连接；无 ON=CROSS JOIN。
- **信号词"哪类数据源所有用户都能用"** → 系统数据源（用户数据源仅创建者+本机；文件数据源是 3.0 新增、面向企业用户）。
- **信号词"应用程序能否直接存取数据库"** → 不能，须经驱动程序管理器提交给 DBMS 驱动程序，由驱动程序实现对数据源的操作并把结果返回。

# E 考场步骤（JOIN 题判定流程）

1. **认类型**：题目要"所有 X（包括没配上的）"→ 外连接；只配对 → 内连接；问"两表所有组合"→ 交叉连接。
2. **定保留侧**：谁的数据不能丢，谁写 JOIN 左边并配 LEFT；题目说"以 X 表为主体"→ X 是保留侧。
3. **写 ON**：连接条件放 ON（两表可比的同名或同义列，如 学生.专业代码=专业.专业代码）；过滤条件若是"保留侧不受影响"的（如 成绩>=70 AND 成绩<=80）放 ON 或 WHERE 等价。
4. **算行数**：结果行 = 配上的行数 + 保留侧没配上的行数；配上的行数按连接字段值逐值配对相加，不是简单相乘（笛卡儿积才是相乘）。
5. **查别名**：多表同名列必须加表名前缀；自身连接必须双别名；长表名建议 AS 起短别名（S、C、CN）。
6. **核 NULL**：外连接里没配上的行，非保留侧各列全 NULL；若结果要求"成绩为空也算"，正是外连接的特征。

# B 边界 ★（失分点与混淆表）

## 失分点

- **LEFT JOIN 后在 WHERE 里过滤保留侧的补 NULL 列（如 `WHERE 成绩>=60`）→ 没配上的行被剔掉，外连接退化成内连接。** 教材例5.34 把成绩条件放进 ON 的三表连接（内连接语境）是合法的，但外连接下把"右表列"条件写进 WHERE 就是经典陷阱。判断标准：条件若会筛掉"补 NULL 的保留行"，就该挪进 ON。
- **方向反了**：`A RIGHT JOIN B` 保留的是 B 不是 A；只记"LEFT=左表全留"即可，RIGHT 一律可用交换表序+LEFT 替代理解。
- **笛卡儿积行列数**：行相乘列相加，与 JOIN 后行数混算。
- **数据源 ≠ 数据库**：DSN 只是"表达一个 ODBC 驱动和 DBMS 特殊连接的命名"。
- **INNER 关键字**：内连接的 INNER 可省略，写 JOIN 默认就是内连接，不是外连接。

## 混淆表一：ODBC 四层 vs ADO 三成员

| | ODBC | ADO |
|---|---|---|
| 结构 | 四层（应用/驱动程序管理器/DBMS 驱动/数据源） | 对象模型（Connection/Command/Recordset/Field + Parameter/Error/Properties） |
| 性质 | 基于 SQL 的标准接口 API（过程式） | 构建于 OLE DB 之上、面向对象、与语言无关 |
| ASP 重点 | 需配 DSN（ASP 要用系统 DSN，不能用用户 DSN） | connection/command/recordset 三对象 |
| 上位关系 | 被 OLE DB 封装 | ADO→OLE DB→（可经 ODBC 桥）→数据库 |

## 混淆表二：与 D3 单表查询的边界

| 信号 | 归属 |
|---|---|
| 单表 WHERE/GROUP BY/聚合 | D3 单表查询 |
| FROM 出现两个以上表 / JOIN 关键字 | D4 连接 |
| 子查询（括号内嵌 SELECT） | D5/D6 域（连接与子查询"某些可互换，某些不能"是 ch05 原话，互换细节不归本单元） |
| INSERT…SELECT 多表取数 | 数据操作域，但内部 JOIN 写法按本单元规则 |

## 补充辨析（高频小考点）

- **数据源三分类**（ch12 §12.1.1）：用户数据源=只有创建者能用、只能在所定义的计算机上用；系统数据源=所有用户及以服务方式运行的程序均可用；文件数据源=ODBC 3.0 以上版本新增。考"哪种数据源所有用户可用"→系统数据源。
- **OLE DB 一句话定位**：COM 组件接口，封装 ODBC 功能，数据源既可以是 DBMS（SQL Server/Oracle/Access），也可以是非 DBMS（文件系统、电子邮件、电子表格、目录服务）。
- **ADO 六大功能挑两个必记**：独立创建对象（不必按层次逐级创建）、成批更新（本地缓存改动，一次写回服务器）。其余：支持带参数存储过程、多种游标类型、限制返回行数、多记录集。
- **例5.2 数字题备答**：学生表 4 行 5 列 × 专业表 3 行 3 列 → 交叉连接 16 行 8 列。
- **等值连接执行过程叙述**（教材原话逻辑）：取出左表每一条记录，与右表记录逐条比较，连接字段值相等才连接进结果集——等值连接过程类似交叉连接，只是**只保留满足条件的**。
