# D5 索引与视图

## R（修订记录）
OCR 修正：全文"索弓引"→索引；"SOL Server/SerVer"→SQL Server；viewl→view1；INSTERD OF→INSTEAD OF。例6.1 代码行乱序已按语义复原。视图中"聚集索引"统一不再写"聚合索引"。

## I（骨架 + 钩子）
一条主线：**索引和视图都不存数据本体，都作用在数据之上**——索引是空间换时间，视图是定义换简洁。

### 钩子（书里自带，升级版）
> 书查内容靠目录，表查数据靠索引——**索引=书的目录**（教材原文钩子，直接借用：全表扫描=逐页翻书，走索引=先查页码再直翻）。
> **视图=窗户**：窗户外是同一栋建筑（基本表），你只看见想看的那一面，还看不坏它——虚实、单向、可多开几扇窗对着同一面墙（教材"以多种角度观察数据"的钩子化）。
> **聚集 vs 非聚集的体感钩**：聚集索引是"书柜里书已按索书号排好"，非聚集索引只是"贴在柜门上的卡片索引"——书没动，卡片指向书。

### 记忆卡片
1. 索引：列的排序结构 + 物理存储位置，B 树。意义：避免**全表扫描**。
2. 三大代价：占空间（聚集索引≈1.2 倍数据大小）、建/维护耗时、**更新变慢**（表更新→索引随之调整）。
3. 建索引原则：主键一定要建、外键可建、常查列最好建；少涉及列/重复值多的列/text·image·bit 列不建；常更新表避免多索引、索引宜窄；小表建索引可能白亏（优化器宁愿全表扫描却仍要维护索引）。
4. 聚集索引：表数据**物理顺序=索引顺序**，叶层即数据页，**一表一个**（默认主键自动建聚集）；单行与范围查询 IO 更快。
5. 非聚集索引：数据不按键序存，叶层是索引行+行定位器（堆→行ID；有聚集索引→聚集键）；**一表最多 249 个**；默认创建的就是它，且占空间更大。
6. `CREATE [UNIQUE] [CLUSTERED|NONCLUSTERED] INDEX 索引名 ON 表(列[ASC|DESC])`；复合索引≤16 列、组合长度≤900B。
7. 唯一索引：键值不可重复；SQL Server 为 PRIMARY KEY / UNIQUE 约束**自动生成唯一索引**来强制唯一性（这正是 D1 完整性与本单元的接缝）。
8. 视图：虚拟表，库里存的只有它的 **SELECT 定义**，查询时动态生成（视图消解）。一切操作最终转回基表。
9. 视图四大优点：简化操作、多角度看同一数据、**逻辑独立性**（重构库隔离）、**安全保护**（藏机密列）。也可藏 GROUP BY 等统计概要（行列子集/连接/联合/统计概要/视图套视图）。
10. 类型三条：标准视图 / **索引视图**（可建唯一聚集索引，物理存储，查询提速）/ **分区视图**（跨服务器 UNION）。
11. `CREATE VIEW 视图名[(列名...)] [WITH ENCRYPTION|SCHEMABINDING] AS 子查询 [WITH CHECK OPTION]`；嵌套≤32 层，一个视图可引≤1024 列；通过视图查询没有任何限制。
12. 维护一句话：碎片检查 `DBCC SHOWCONTIG`（扫描密度理想值 100%）、整理 `DBCC INDEXDEFRAG`。

## A1（书中例题）
```sql
-- 例6.1 教师表"专业"列非聚集索引
USE student GO
CREATE INDEX js_zy_index ON 教师(专业) GO

-- 索引应用举例 1：复合非聚集索引
CREATE INDEX xb_zy_index ON 学生(系部代码, 专业代码)

-- 2：聚集复合索引
CREATE CLUSTERED INDEX jskc_index ON 教师任课(教师编号, 课程号)

-- 3：唯一、聚集、复合
CREATE UNIQUE CLUSTERED INDEX jxkc_zy_index
ON 教学计划(课程号, 专业代码)
WITH PAD_INDEX, FILLFACTOR = 70, IGNORE_DUP_KEY

-- 例6.9 单表视图
CREATE VIEW view1 AS
SELECT 学号, 姓名, 出生日期 FROM dbo.学生

-- 例6.10 多表连接视图（本书最常考形态）
CREATE VIEW view2 AS
SELECT 学生.学号, 学生.姓名, ..., 系部.系部名称
FROM dbo.学生 INNER JOIN dbo.系部 ON 学生.系部代码 = 系部.系部代码
WHERE 系部.系部名称 = '计算机系'

-- 例6.12 索引视图（SCHEMABINDING + 唯一聚集索引）
CREATE VIEW view4 WITH SCHEMABINDING AS
SELECT 姓名, 学号 FROM dbo.学生 WHERE 系部代码='01'
GO
CREATE UNIQUE CLUSTERED INDEX 姓名 ON view4(姓名)

-- WITH CHECK OPTION：改走必须留在"围栏"内
CREATE VIEW view1 WITH CHECK OPTION AS ...

-- 操作：EXEC sp_helpindex 教师 / EXEC sp_rename 'dbo.教师.js_zy_index','js_zyindex'
-- DROP INDEX 学生.xm_学生 / DROP VIEW view2 / sp_helptext view2 查定义
```

## E（考场步骤）
简答三件套：
1. **索引题三段式**：①意义（对象概念→排序结构→避免全表扫描→加快检索）②代价三段（空间、创建维护耗时、更新变慢）③原则（主键必建→外键可建→常查列好建→少涉及/重复多/大类型列不建）。判停条件：三段各自落地 ≥2 点即可收笔。
2. **视图题两头起**：定性（虚表：仅存定义、动态生成、操作转回基表）→ 优点四点逐一列。
3. **聚集非聚集对比题**：按"物理顺序是否一致 / 叶层是否数据页 / 可建个数 / 性能"四格填。
判停条件：全部数字钩（1 个聚集、249 个非聚集、16 列、900B、1024 列、32 层、8KB）已核对一遍，与题干数字一致才停笔。

## B（边界★·失分点）
- **失分点1（★独立反例条目：视图更新规则）**：对视图的更新最终转回对基表的更新，但**一个 UPDATE/INSERT 语句只能涉及一个基表**——判据：这次修改能否唯一还原为某一张基表上的某一行？
- 反例（两表连接视图）：`view2`（学生 JOIN 系部）上 `UPDATE view2 SET 姓名='王洪' WHERE 学号='...'` **可以**（改动只落在"学生"一张基表的行、列，且该列非空值属性可满足）；但想同一语句里把"系部名称"一起改 → 报错（跨两个基表）。
- 反例（连接+筛选视图）：`view1`（学生 JOIN 课程注册 JOIN 课程）上 `INSERT INTO view1 VALUES(...)` 直接拒绝——该行无法唯一映射回任何一张基表的完整行（基表"课程注册"还有视图中未出现的不允许空值的列）。删除同理。
- WITH CHECK OPTION 反例：视图限定 WHERE 成绩>=60，若把某行成绩改成 50，该行会从视图"消失" → 修改被整体回绝。
- **失分点2**：索引越多越好？——反例：报表表（只查不改）可以多建；流水表（时刻有 INSERT/UPDATE）多建索引反而“维护费时、更新变慢”，且占磁盘空间（聚集索引≈1.2×数据量）。小表建索引可能优化器根本不用，但仍要持续维护。
- **失分点3**：基表删除→视图不能使用（一般不自动删除，需手动 DROP VIEW）；用 `SCHEMABINDING` 可阻止误删基表。
- 与 D1 混淆表：
| | D1（参照完整性） | D5（索引） |
|---|---|---|
| 唯一性 | PRIMARY KEY/UNIQUE **约束** | 约束**自动生成**的唯一（聚集）索引 |
| 删除 | 删约束 | 删约束（或 DROP INDEX 用户索引） |
- 与 D3 混淆表：
| | D3（基本表单表查询） | D5（视图查询） |
|---|---|---|
| 数据位置 | 存在表里 | 库里只有 SELECT 定义，动态生成 |
| 查询步骤 | 直接 | 多一步"视图消解"转回基表 |
| 更新 | 任意 | 受可更新判据限制 |

## 快问快答（考前自查）
1. 索引是什么？→ 列的排序结构 + 存储位置，B 树形态。
2. 聚集/非聚集一句话差异？→ 物理（存储）顺序 vs 逻辑顺序；叶层数据页 vs 行定位器。
3. 每表能建几个聚集？→ 1；非聚集上限？→ 249。
4. 删聚集索引的连带反应？→ 该表所有非聚集索引被重建。
5. 看表索引信息用什么命令？→ sp_helpindex。
6. 视图消解是什么？→ 把对视图的查询翻译成对基表的查询。
7. 建视图后列名必须显式列出的三种情况？→ 函数/表达式列；连接同名列；改列名。
8. 索引视图与标准视图差别？→ 有唯一聚集索引才物化存储，查询提速。
9. SHOWPLAN / STATISTICS IO 各管什么？→ 执行计划 vs 磁盘活动量。
10. WITH ENCRYPTION 之后还能 sp_helptext？→ 不能，视图定义已加密。
