## 候选 1：批处理 / GO / 语法错误 vs 执行错误（ch09.1）★V1+V2 通过
- 批处理 = 一条或多条 T-SQL 语句集合，一次性发送，编译成一个执行计划。
- GO = 批处理结束标记；**不是 T-SQL 语句**，是客户端实用程序（SSMS 查询窗口）识别的命令；服务器收到的批不含 GO；GO 行上只能有注释不能有其他语句。
- 语法错误（如引用不存在对象）→整个批不能编译执行；执行错误（如违反约束）→仅终止从出错处到批末尾的执行，不影响之前已执行语句和其他批。
- 批处理 6 条限制（CREATE PROCEDURE/RULE/TRIGGER/DEFAULT/VIEW 不能与其他语句同批；删对象后不能同批再引用；变量不能跨批引用；规则/默认值绑定后不能立即同批使用；CHECK 约束定义后不能立即同批使用；改列名后不能立即同批引用新列名）。
- 脚本 = 存于文件的若干批处理序列；无 GO 则整体单批执行。
- 注释两类：行内 `--`（至行尾）；块注释 `/* */`（可多行、可嵌入代码行，但**不能跨越批处理**）。
- 考点价值：简答（GO 是不是 T-SQL 语句？）+ 判断题（多行注释能不能跨 GO？不能）。

## 候选 2：事务定义 + ACID 四属性展开（ch09.2）★★V1+V2+V3' 通过（必考）
- 事务 = SQL Server 中的执行单元，由一系列 T-SQL 语句组成；要么全部成功完成，要么失败全部复原（回滚）。
- 事务四原则统称 ACID（书中原文展开，必背）：
  1. 原子性 atomicity：要么完成事务中所有操作，要么所有操作都不运行；某语句失败，则作为事务一部分的所有语句都不会运行。
  2. 一致性 consistency：事务完成或失败时，数据库处于一致状态；由事务引发的状态变化是一致的。
  3. 隔离性 isolation：事务是独立的，不与数据库的其他事务交互或冲突。
  4. 持久性 durability：事务成功完成后对数据的改变是永久的；即使系统掉电或服务器崩溃，重启后事务结果仍完整。
- 事务的提出目的：防止多用户访问同一数据时造成的数据异常（并发访问干扰）。
- 事务分类：显式事务（用户用 BEGIN TRANSACTION 定义）/ 隐式事务（系统提供，一条语句即一个事务，如 CREATE、ALTER、DROP、INSERT、DELETE、UPDATE、SELECT、GRANT、REVOKE、TRUNCATE TABLE、FETCH、OPEN、DROP TABLE 等）。
- 显式事务三句：BEGIN TRANSACTION 开始；COMMIT（提交，永久生效）/ROLLBACK（撤销，回滚）结束。**必须显式指定结束**，否则从事务开始到连接关闭之间的所有操作都被当作一个事务。

## 候选 3：事务处理语句四件套 + @@TRANCOUNT / @@ERROR（ch09.2.2-9.2.3）V1 通过
- BEGIN TRANSACTION：开始事务（可命名、可 WITH MARK 日志标记；TRANSACTION 可只写前 4 字符 TRAN）。
- COMMIT TRANSACTION：提交，自事务开始的所有修改成为数据库永久部分；@@TRANCOUNT 减 1。COMMIT WORK 与其差别：**COMMIT WORK 不带参数**。
- ROLLBACK TRANSACTION：撤销事务到起点或指定**保存点**；撤销到开始点则 @@TRANCOUNT 减 1，只撤销到保存点则 @@TRANCOUNT 不变。
- SAVE TRANSACTION：设置保存点（回滚停止点）。
- @@TRANCOUNT 全局变量：当前连接的活动事务数。
- @@ERROR：记录**最后执行的那条** T-SQL 语句的错误代码，0=成功非 0=出错；后续成功语句会把它清 0，所以 IF @@ERROR<>0 判断必须紧跟出错语句（例 9.3 的教训，好考点）。
- 分布式事务：多服务器事务，MSDTC 服务支持；BEGIN DISTRIBUTED TRANSACTION。

## 候选 4：锁机制三件套（ch09.2.4）V1 通过
- 锁 = 多用户环境中对正在使用资源的限制；保证事务隔离性/数据库一致性的并发控制手段。
- 锁定粒度（由小到大）：行、页、扩展盘区、表、数据库。粒度小→开销大并发度高；粒度大→开销小并发度低。升级基于 2% 标准（行级占比>2% 升页锁，页级占比>2% 升表锁）。
- 三类锁：共享锁 S/读锁（SELECT 加；可多个共存、阻止修改；读完即释放）；排他锁 X/写锁（INSERT/DELETE/UPDATE 加；一个资源只能一个排他锁；禁止任何其他锁）；更新锁（UPDATE 两阶段：定位读=共享，改数据时升为排他；提高读并行性）。
- 死锁：两事务循环等待对方资源。预防=一次封锁法/顺序封锁法；诊断=超时法/事务等待图（有回路即死锁）；解除=最小代价牺牲法（撤销代价最小事务，并恢复其已做修改）。

## 候选 5：变量 DECLARE / SELECT / SET / PRINT / 流程控制（ch09.3-9.4）★V1+V2 通过
- 全局变量 @@开头、系统定义维护 32 个、只能读不能写、本质是**系统函数**；常用的：@@ERROR（上条语句错误码）、@@ROWCOUNT（上条语句影响行数）、@@TRANCOUNT（活动事务数）、@@IDENTITY、@@VERSION、@@SERVERNAME、@@SPID。
- 局部变量 @开头、用户定义、作用域=声明处到所在批处理/可编程对象结束。
- DECLARE @x 类型 [初始值]；未赋值则为 NULL；不能声明为 text/ntext/image 类型。
- 赋值：**SELECT 一条可赋多个变量；SET 一条只能赋一个**（高频判断题）。复合赋值 @a+=1。
- PRINT 输出到"消息"窗格；SELECT 输出到"结果"窗格。
- BEGIN...END 语句块（可嵌套）；IF...ELSE；CASE 两格式（简单 CASE / 搜索 CASE，均无 ELSE 时返回 NULL）；WHILE（BREAK 退出、CONTINUE 回循环头，可嵌套，内层 BREAK 只退出本层跳到外层继续）；WAITFOR DELAY/TIME；PRINT。

## 候选 6：存储过程概念/优点/五类型（ch10.1.1-10.1.2）★V1+V2 通过  [OCR 已修：存诸过程→存储过程]
- 存储过程 = 为实现某个特定任务，将一组**预编译**的 SQL 语句（集）存放在服务器（数据库对象）上，用户按名称执行；编译好的代码保存在高速缓存中便于以后调用，提高执行效率。
- 特点/优点（书中）：①接收输入参数并以**输出参数**形式返回多个值；②包含执行数据库操作（可调用其他过程）的编程语句；③向调用者返回状态值表明成功或失败。另：预编译+缓存→执行快；可重用、模块化。
- 五类：系统（master 库、sp_ 前缀，如 sp_help）、本地（用户库自建）、临时（#局部 / ##全局）、远程（传统功能，仅用于分布式查询）、扩展（xp_ 前缀，DLL 实现，只能存在 master 库中）。

## 候选 7：存储过程创建/执行/修改/删除+查看 四动词（ch10.1.3）★★V2 通过  [OCR 已修]
- 创建二法：对象资源管理器 / T-SQL。CREATE PROC[EDURE] 名 [@参数 数据类型 [OUT|OUTPUT]=[默认]] [WITH RECOMPILE|ENCRYPTION] AS 语句。
- 注意：只能在当前数据库创建；名称遵守标识符规则；**不能与其他语句组合在同一批处理**。
- 执行：EXEC[UTE] 过程名 [参数值|@变量 [OUTPUT]]；若存储过程是批处理中**第一条语句**，EXECUTE 可省略直接写过程名。
- 查看：sp_helptext（文本）、sp_depends（相关性）、sp_help（一般信息）。
- 修改：ALTER PROCEDURE（不更改权限、不影响相关存储过程或触发器）。
- 删除：DROP PROCEDURE 名[,n]（可一次删多个/整组 ;number）。
- 重新编译三法：创建时 WITH RECOMPILE / 执行时 EXEC ... WITH RECOMPILE / sp_recompile 对象名（下次运行重编译）。

## 候选 9：触发器概念/三要素/优点（ch10.2.1-10.2.2）★★V2+V3' 通过
- 触发器 = 捆绑在基表（或视图）上的预编译 SQL 语句集，是**特殊类型的存储过程**，事件驱动，数据完整性实现手段之一。
- 组成三部分：事件（对数据库的定义/操纵操作）、条件（测试条件）、动作（满足条件时执行，可撤销事件）。
- 触发器 SQL99 之后才列入 SQL 标准（各 DBMS 语法互不兼容）。
- 特点：①与表紧密相连，可看作表定义的一部分；②**不可能通过名称被直接调用，更不允许使用参数**，用户对表中数据修改时自动执行；③可以做比 CHECK 约束更复杂的完整性检查（CHECK 不能引用其他表中的列，触发器可以）。
- 优点：自动执行；级联操作（一表触发、多表操作）；比 CHECK 更复杂（可引用其他表列）；可评估修改前后状态；一个表可同时存在多个不同操作的触发器。

## 候选 10：触发器类型 + 虚表 inserted/deleted（ch10.2.3-10.2.4）★★V2 通过
- 类型两大类：DML 触发器（触发事件 INSERT/UPDATE/DELETE）与 DDL 触发器（CREATE/ALTER/DROP/GRANT/DENY/REVOKE 等，只有 AFTER 一种响应时间）。另 CLR 触发器（.NET，本章不讲）。
- 按事件：INSERT 型/UPDATE 型/DELETE 型。
- 按响应时间：AFTER（FOR=AFTER，后触发器，只能定义在表上不能在视图上，每个操作可建多个）、INSTEAD OF（替代触发器，先取消事件语句、以动作语句替代；表和视图都可定义，每个操作只能一个）。
- **虚（逻辑）表** inserted/deleted：触发器激发时由系统自动创建于高速缓存中的逻辑表，触发器执行结束自动删除。
  - INSERT 触发：新行写入 **inserted**；触发器表与 inserted 有相同记录。
  - DELETE 触发：被删行写入 **deleted**；触发器表与 deleted 没有相同记录（记录已消失）。
  - UPDATE 触发 = 先删旧后插新：旧记录进 deleted、新记录进 inserted，"两表各一份"。
  - IF UPDATE(列) 监视指定列更新。
- TRUNCATE TABLE 是不记录日志的操作：**不会触发 DELETE 触发器**，触发器动作里也不能含 TRUNCATE TABLE 语句。
- 嵌套：触发器中语句可激发其他触发器，默认允许嵌套、最多 **32 层**；默认不允许**迭代调用（自己调用自己）**。递归（直接/间接）最多 **16 层**，超 17 层即回滚；默认禁用递归，可在数据库属性启用。

## 候选 11：存储过程 vs 触发器 根本区别（ch10 综合）★V3' 通过（必考）
- 存储过程：**显式调用**——用户/程序用 EXEC 或过程名直接调用；可用参数；不属于任何表。
- 触发器：**自动触发**——不能按名称直接调用、不能带参数，附在表/视图上，数据修改（DML 事件）发生时自动激发。
- 触发器不能被 EXEC 调用、不能传参。（书 10.2.2 原文："不可能通过名称被直接调用，更不允许使用参数"）

## 候选 12：触发器生命周期动词 + DDL 触发器（ch10.2.4-10.2.5）V1 通过
- 创建前注意：CREATE TRIGGER 必须是**批处理中的第一条语句**；只能当前库创建；不能在临时表/系统表上建（触发器可引用临时表但不能引用系统表）；WRITETEXT 不引发 INSERT/UPDATE 触发器。
- 查看：sp_help / sp_helptext / sp_depends，另有专门 **sp_helptrigger 表名**。
- 修改：ALTER TRIGGER（整体重定义）；重命名 sp_rename；禁用/启用：ALTER TABLE 表名 触发器名 ENABLE|DISABLE。
- 删除：DROP TRIGGER 名[,n]；删表的同时删除表上所有触发器；删触发器不影响表中数据。
- DML 触发器 ON 表|视图；DDL 触发器 ON ALL SERVER（服务器级）| DATABASE（数据库级），响应时间只有 AFTER，无 INSTEAD OF。例 10.23：SafetyXS ON DATABASE FOR DROP_TABLE,ALTER_TABLE → PRINT+ROLLBACK 防止删改表。
