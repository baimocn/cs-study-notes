## 池① 决策框架（判定类规则）

- C1-1 完整性归类框架：给定约束/场景判定属于四类完整性中的哪类，并映射到六类约束。[ch07 7.1、7.2；ch01 1.2.1"关系模型的数据完整性"]
- C1-2 主键 vs UNIQUE 选型：唯一+非空→PRIMARY KEY；唯一但可空→UNIQUE；主键约束优先于 UNIQUE 索引。[ch07 7.2]
- C1-3 完整性实现方案开销阶梯：数据类型 < 默认/规则 < 约束 < 触发器，功能越强开销越高，选够用的最低档。[ch07 7.8]
- C1-4 主表/从表判定：以某属性为主键的表=主表，以该属性为外键的表=从表。[ch01 1.2.1]
- C1-5 E-R 联系→关系模式主键判定：1:1 可独立或并入任一端（候选码=各端键）；1:n 并入 n 端（键=n 端键）；m:n 必独立（键=两端键组合）。[ch01 1.3.4]
- C1-6 范式判定升级链：1NF 属性原子→2NF 消非主属性部分依赖→3NF 消传递依赖→BCNF 消主属性对码的部分/传递依赖→4NF 消非平凡非函数多值依赖。[ch01 1.2.2]
- C1-7 模式归属判定：视图=外模式、基本表=模式（逻辑）、索引=内模式（物理）。[ch01 1.1.5；ch01 1.2.1"SQL 语言"节（定义外模式如视图、内模式如索引）]

## 池② 原则/规则

- C2-1 实体完整性规则：主键属性列上的值不能为空（且唯一）。[ch01 1.2.1；ch07 7.1]
- C2-2 参照完整性规则：不能在从表中引用主表中不存在的元组；SQL Server 表现为"三禁"（禁从表插入主表没有的键值、禁改主表键值致从表孤立、禁删从表有对应记录的主表记录）。[ch01 1.2.1；ch07 7.1]
- C2-3 用户定义完整性：针对具体应用的语义约束，其余完整性类型均可承载它。[ch01 1.2.1；ch07 7.1]
- C2-4 关系模型三组成部分：数据结构、关系操作、数据完整性。[ch01 1.2.1]
- C2-5 约束优先原则：使用约束优先于使用触发器、规则和默认值；查询优化器也使用约束定义生成执行计划。[ch07 7.2]
- C2-6 每个表都应有一个主键；无明确主键需求的表建议用整数序列作主键。[ch07 7.2]
- C2-7 约束作用域规则：约束分字段约束与表约束；约束涉及一个以上字段时必须用表约束。[ch07 7.2]
- C2-8 函数依赖是语义范畴概念，只能根据语义确定，不能用数学证明（姓名→年龄仅在无重名时成立）。[ch01 1.2.2]
- C2-9 规范化的本质是"单一化"：通过分解使一个关系表示一事或一物。[ch01 1.2.2]

## 池③ 案例

- C3-1 学生-选课-课程合一表 vs 拆三表：合一表产生数据冗余、修改异常、插入异常、删除异常四类问题。[ch01 1.2.2]
- C3-2 选课1（学号,课程号,系部代码,出生日期,成绩）不满足 2NF：系部代码、出生日期只部分依赖于（学号,课程号）。[ch01 1.2.2]
- C3-3 学生2（学号,…,系名,系宿舍楼）不满足 3NF：系宿舍楼传递依赖于学号（学号→系名→系宿舍楼）。[ch01 1.2.2]
- C3-4 教学（学生,教师,课程）不满足 BCNF：教师是决定因素但不包含码。[ch01 1.2.2]
- C3-5 授课（课程,教师,参考书）不满足 4NF：课程→→教师、课程→→参考书均为非平凡多值依赖且课程不是码。[ch01 1.2.2]
- C3-6 约束创建实例族：例7.1/7.2 教材代码主键（建表时/ALTER 后补）；例7.3 书号 UNIQUE；例7.4 学分 CHECK 1~7；例7.5 入学时间 CHECK（>'1978-01-01' AND <GETDATE()）；例7.6 注册时间 DEFAULT GETDATE()；例7.7 学历 DEFAULT '本科'；例7.8 班级.专业代码 FOREIGN KEY REFERENCES 专业。[ch07 7.3]
- C3-7 例7.11 规则 xb_rule 绑定"学生.性别"限男/女；例7.13 默认对象 df_xf 绑定课程注册.学分=4。[ch07 7.6、7.7]
- C3-8 学生选课 E-R：学生-课程 m:n、课程-教材 1:1（一门课只用一种教材）。[ch01 1.1.4]

## 池⑤ 关键术语

- C5-1 信息（客观反映）/数据（信息的载体）/数据管理（分类组织编码存储检索维护，数据处理的中心问题）。[ch01 1.1.1]（标题 OCR"信息、娄"应为"信息、数据"）
- C5-2 信息世界七概念：实体、属性、关键字、域、实体型、实体集、联系（1:1 / 1:n / m:n）。[ch01 1.1.4]
- C5-3 E-R 图符号：矩形=实体型、椭圆=属性、菱形=联系（联系也可以有属性）。[ch01 1.1.4]
- C5-4 四种结构数据模型：层次、网状、关系、面向对象；关系模型优点三条（数学基础严格、概念单一、存取路径对用户透明）。[ch01 1.1.4]
- C5-5 关系模型术语族：属性/值域、关系模式（行定义=型）、元组（行=值）、候选码、主码、非主属性、外键（不是本表码[或只是码的一部分]却是另一关系的码）。[ch01 1.2.1]
- C5-6 三级模式名称与别名：外模式=子模式=用户模式（可有多个）；模式=逻辑模式（仅一个）；内模式=存储模式（仅一个）。[ch01 1.1.5]
- C5-7 两级映像与两个独立性：外模式/模式映像→逻辑独立性；模式/内模式映像→物理独立性。[ch01 1.1.5]
- C5-8 四类完整性名称：实体、域、参照、用户定义。[ch07 7.1]
- C5-9 六类约束名称：NOT NULL、CHECK、UNIQUE、PRIMARY KEY、FOREIGN KEY、DEFAULT。[ch07 7.2]
- C5-10 规则与默认对象生命周期四步：创建→绑定→解绑→删除（DROP 前必须先解绑）。[ch07 7.6、7.7]
- C5-11 DB / DBMS / DBS / DBA 定义（DBMS 位于用户与操作系统之间；DBS 广义含 DB、DBMS、开发工具、应用程序、DBA 和用户）。[ch01 1.1.3]
- C5-12 数据管理三阶段：人工管理、文件系统、数据库系统。[ch01 1.1.2]
- C5-13 DDL（数据定义语言）/ DML（数据操纵语言）。[ch01 1.1.3]
- C5-14 概念模型 vs 结构数据模型二分类（用户观点/计算机观点）。[ch01 1.1.4；1.3.3 佐证]
