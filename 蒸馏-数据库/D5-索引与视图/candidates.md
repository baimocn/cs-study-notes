## C1 索引的概念与意义（目录钩子）
索引是保存表中一列或几列排序结构的数据库对象。教材原文自带钩子：**索引之于表 = 目录之于书**。查数据两种方式：全表扫描（一页页翻书）vs 走索引（先查目录再翻页码）。意义=加快检索、避免全表扫描。
- V1：✅（6.1.2"使用索引的意义"原段）
- V2：✅ 常考简答"什么是索引/使用索引的意义"
- V3'：★★★ 练习题1原文原题

## C2 使用索引的代价（反直觉点）
三条代价：①占额外物理存储空间（聚集索引约1.2倍数据大小）；②创建维护耗时；③表更新时索引需重建/调整 → 降低数据维护速度。
- V2：✅ 反直觉："索引不是越多越好"
- V3'：★★★ 判断题高发"索引越多越好（×）"

## C3 建立索引的原则
主键一定要建；外键可建；经常查询的列最好建；很少涉及的列、重复值多的列不建；text/image/bit 类型列不建；经常更新的表避免过多索引、索引宜窄；小表建索引可能反而不划算。
- V2：✅ 简答高频
- V3'：★★★

## C4 聚集索引 vs 非聚集索引（结构级对比，独立反例条目素材）
聚集索引：数据行物理存储顺序与索引顺序完全相同，叶层=数据页；**每表只能建一个**（默认主键自动建聚集）；适合单行查找、范围查询，IO 更快。
非聚集：数据行不按索引键排序存储，叶层不含数据页（索引行+行定位器）；每表最多 **249 个**非聚集索引；速度稍慢、占空间更大；可定义在堆、聚集索引表或索引视图上。
- V1：✅ 6.2 整节
- V3'：★★★ 练习题2原文原题；判断题"聚集索引一个表可建多个（×）"

## C5 CREATE INDEX 语法与例题
`CREATE [UNIQUE][CLUSTERED|NONCLUSTERED] INDEX 索引名 ON 表(列[ASC|DESC][,...n]) [WITH ...]`。省略 NONCLUSTERED 项默认非聚集。书中例6.1（教师.专业 非聚集索引 js_zy_index）、三例：复合索引 xb_zy_index、聚集复合 jskc_index、唯一聚集复合 jxkc_zy_index（FILLFACTOR=70, IGNORE DUP KEY）。注意：需 DB 空间（建聚集时复制表）；删除聚集索引时所有非聚集索引将重建；删 PRIMARY KEY/UNIQUE 约束索引须先删约束。sp_helpindex 查看索引；sp_rename 重命名；DROP INDEX 表名.索引名。
- V3'：★★ 操作题/填空（默认类型、"最多249/16列/900B"）

## C6 视图 = 虚拟表（窗户/筛选器钩子）
视图是一个虚拟表，其内容由查询定义（存储的是 SELECT 语句，不存数据）；对视图所引用的基表，视图作用类似筛选，引用时动态生成。基表删除→视图不能继续使用（一般不自动删除）。一切对视图的操作最终转换为对基表的操作（视图消解）。一个视图最多引用1024个字段，嵌套≤32层。
- V1 / V2 / V3'：均 ✅，视图概念必考

## C7 视图的四大优点
①简化用户操作（把多表连接藏起来）；②多角度看待同一数据；③对重构数据库提供一定程度的逻辑独立性；④对机密数据提供安全保护。
- V3'：★★★ 简答原题（练习题7"视图的作用"）

## C8 CREATE VIEW 语法 + WITH CHECK OPTION
`CREATE VIEW 视图名[(列名,...)] [WITH ENCRYPTION|SCHEMABINDING] AS <子查询> [WITH CHECK OPTION]`。必须显式指定列名的三种情况：目标列为函数/表达式；多表连接选出同名列；需改名。WITH CHECK OPTION=通过视图 INSERT/UPDATE/DELETE 的行必须仍满足视图定义中的条件。书中例：view1（班级成绩三表连接）、view2（计算机系学生）、view3（SCHEMABINDING 防删基表）、view4（索引视图+唯一聚集索引）、view7（加密）、view8（隐藏成绩字段的安全视图）。
- V3'：★★★ 

## C9 可更新视图判据（★红线·独立反例条目）
对视图的更新最终转成对基表的更新。准则：①DBMS 必须能明确解析对视图所引用基表中特定行的修改；**一个语句不能对多个基表进行修改——UPDATE/INSERT 中的列必须属于同一基表**（多表连接视图通常不可更新，练习题12即此考点）；②基表中不允许空值的列必须在 INSERT/DEFAULT 中给出值；③修改须符合基表约束。WITH CHECK OPTION 保证修改后行仍留在视图范围内，否则拒绝。
- V2：✅ 新题（教材练习题12"尝试插入删除更新，若不能为什么"）
- V3'：★★★ 高频陷阱/判断题

## C10 视图查询 vs 基表查询（消解机制）
查视图无限制；DBMS 先有效性检查→从数据字典取出视图定义→把子查询与用户查询结合转成对基表的查询（视图消解）。区别：基表存数据，视图存定义；查询视图多一步消解。
- V3'：★★ 练习题9

## C11 索引分析与维护（边缘保留）
SET SHOWPLAN_ALL / SET STATISTICS IO 分析；DBCC SHOWCONTIG 看碎片（扫描密度理想值100%）；DBCC INDEXDEFRAG 整理碎片。
- V3'：★ 练习题5，偶考

## C12 页/8KB/存储结构（淘汰候选）
页=8KB，96B页首，八种页类型；B树根/中间/叶节点。库存性强、考分低。
