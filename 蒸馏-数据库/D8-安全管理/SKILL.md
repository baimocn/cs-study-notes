# D8 安全管理（SQL Server 2012 · ch11）

## R 引用（OCR 已修，≤150 字）

> 「在 SQL Server 2012 中有两类登录账户：一类是登录服务器的登录账号（Login Name），另外一类是使用数据库的用户账号（User Name）。登录账号属于服务器的层面，本身并不能让用户访问服务器中的数据库，而登录者要求使用服务器中的数据库时，必须要有用户账号才能存取数据库。就如同在公司门口先刷卡进入（登录服务器），然后再拿钥匙打开自己的办公室（进入数据库）一样。」

—— ch11 §11.2（约 40 字删节；OCR 修复见文末审计）

## I 骨架 + 钩子

### 知识骨架（五层，逐层收紧）

1. **验证模式**（进门方式）
   - Windows 验证：完全采用 Windows 服务器的验证，能登录 Windows 的用户才能登录 SQL Server。
   - 混合验证：Windows 用户 + 独立 SQL Server 用户均可登录；非 Windows 系统可经网络连接。
   - 判据一句话：是否放行"SQL Server 独立登录账号"。
   - 设置/修改：SSMS→右键服务器→属性→安全性→选验证方式；改完必须停止再重启 SQL Server 服务才生效。
2. **两级账号**（两道闸）
   - 登录名（Login Name）：服务器层，管"能不能连上服务器"，本身不能访问任何数据库。
   - 数据库用户（User Name）：数据库层，由登录名映射而来；用户信息存于该库 sysusers 表；用户不设密码。
   - 数量规则：一个登录账号在一个数据库中只能有一个用户账号；可在不同数据库各有一个。
   - 陷阱：登录名对某库有访问权 ≠ 能对库中对象插入更新——还须设置用户账号权限。
   - sa：超级登录账号，服务器范围内一切权限；安装后密码为空，装完系统第一件事是设密码。
3. **角色**（权限的打包，类似 Windows 用户组）
   - 服务器角色：管服务器层的登录名；数据库角色：管单个数据库的用户。
   - 固定数据库角色 10 个 + 应用程序角色（控制应用程序存取数据库，本身不含任何成员）。
   - public：最基本角色，每个用户至少属于它；新用户加入数据库时自动加入 public。
4. **权限**（能干什么，三分类）
   - 对象权限：对表/视图/存储过程等对象的操作权。
   - 语句权限：CREATE TABLE、BACKUP DATABASE 等语句的使用权（相当于 DDL 类）。
   - 隐含权限：sysadmin 成员、dbo、对象所有者系统预定义，不需要授予、也不能设置。
5. **权限管理三动词**（GRANT/REVOKE/DENY，语义见 A2 与 B）
   - 授予=GRANT（允许）；取消=REVOKE（不允许，中立足点）；拒绝=DENY（显式禁止）。
   - 冲突裁决：三种权限冲突时，拒绝访问权限起作用。

### 钩子（本章就记三句）

- **两级门禁**：登录名 = 大门钥匙（能进机房大楼），数据库用户 = 房间通行证（能进具体数据库的房间），权限 = 房间里能碰哪张桌子。有钥匙没通行证 → 连得上服务器、打不开数据库。
- **权限账本**：GRANT = 记一笔"允许"存入；REVOKE = 把这笔存入划掉（余额回零、回到中立，以后还能再存）；DENY = 盖"冻结"章（之后存多少、角色转来多少，一律冻结）。
- **DENY 一票否决**：用户属于 10 个角色、9 个都 GRANT，只要有 1 个 DENY → 拒绝。

### 角色速查（填空/选择弹药）

- 服务器角色（管"楼"，配给登录名，共 9 个）：sysadmin（执行任何活动）、serveradmin（设置服务器范围配置选项、关闭服务器）、setupadmin、securityadmin（管理服务器登录、读取错误日志、更改密码）、processadmin、dbcreator（创建/更改/删除数据库）、diskadmin（管理磁盘文件）、bulkadmin（执行大容量插入）、public（所有用户都具有）。
- 固定数据库角色（管"房间"，配给用户，共 10 个）：db_owner（数据库中有全部权限）、db_accessadmin（添加或删除用户 ID）、db_securityadmin（管理全部权限、对象所有权、角色及成员资格）、db_ddladmin（可发所有 DDL 语句，但不能发 GRANT/REVOKE/DENY）、db_backupoperator（DBCC CHECKPOINT 和 BACKUP）、db_datareader（选任何用户表的所有数据）、db_datawriter（更改任何用户表的所有数据）、db_denydatareader（不能选任何数据）、db_denydatawriter（不能更改任何数据）、public。
- 记法：两个 denydata 角色是"预置黑名单"；带 admin 的管"结构与人"，带 reader/writer 的管"数据进出"。

### 权限三分类速查

| 分类 | 管什么 | 具体内容 | 能否设置 |
|---|---|---|---|
| 对象权限 | 对对象的操作 | 表/视图：SELECT、INSERT、UPDATE、DELETE；字段：SELECT、UPDATE；存储过程：EXECUTE | 能（GRANT/DENY/REVOKE） |
| 语句权限 | 发语句 | CREATE TABLE、CREATE DEFAULT、CREATE RULE、CREATE VIEW、CREATE PROCEDURE、BACKUP DATABASE、BACKUP LOG | 能（GRANT/DENY/REVOKE） |
| 隐含权限 | 系统预定义 | sysadmin 成员、数据库所有者 dbo、数据对象所有者自带 | 不能，也无需授予 |

## A1 书中授权例题（ch11 §11.7 案例：学生管理信息系统）

**问题**：student 库中，studentadm 是系统管理员（全权），stu 是学生账号，只允许读"学生"表。

**操作/规则**（教材用 SSMS 图形操作，等价 SQL 为补充标注）：
1. 验证方式设为混合验证——这样不必先在 Windows 建账号，直接在 SQL Server 里建。
2. 建登录名 studentadm、stu（SQL Server 身份验证 + 密码，默认数据库 student）。
3. "用户映射"映射到 student 库 → 系统自动建同名数据库用户；studentadm 加 db_owner，stu 不加（不加就是普通用户）。
4. 建数据库角色 role_stu：在"安全对象"页添加类型"表"、名为"学生"的对象，把"选择"（SELECT）权限设为"授予"。
5. 把 stu 加入 role_stu。

**结论**：stu 经角色继承获得"学生"表只读权。权限挂在角色上而非用户上——用户会删、角色随库长存，权限不跟着消失；用户多时逐个授权不现实，角色是标准做法。

（补充标注：等价 T-SQL 形如 `GRANT SELECT ON 学生 TO stu`——教材本节只演示 SSMS 步骤，未给 SQL 语句，SQL 形式为标准语义补充。）

## E 考场步骤：授权题作答四步

1. **谁**：分清层——题目说"能登录服务器"→登录名（服务器层）；说"能访问某库/某表"→数据库用户 + 权限（数据库层）。
2. **什么权限**：三分类对号——操作表/视图/存储过程=对象权限；CREATE TABLE、BACKUP DATABASE 等=语句权限；sysadmin、dbo 自带=隐含权限。
3. **在哪个对象上**：表/视图/字段/存储过程/数据库，点名再动手；字段级只有 SELECT、UPDATE 两种。
4. **写 SQL 还是说概念**：SQL 题套 `GRANT 权限 ON 对象 TO 用户`；概念题用"授予/拒绝/取消"三分表述，并点出"冲突时拒绝优先"。

## B 边界★（失分点）

- **模式判据**：两种模式的区别判据是"是否允许 SQL Server 独立登录账号"。能用 SQL Server 身份验证登录 = 混合模式；非 Windows 用户要连库 → 必须混合模式。改模式后必须停止再重启 SQL Server 服务，否则不生效。
- **REVOKE vs DENY 账目区分**：取消（REVOKE）后是"不允许"，但可通过加入角色重新获得允许权；拒绝（DENY）后无法再通过角色获得。三种权限冲突时，拒绝访问权限起作用。一句话：REVOKE 划掉一笔，DENY 冻结整个账户。
- **登录名 ≠ 用户**：登录名对某库有访问权 ≠ 能对库中对象做插入更新；还须设置用户账号的权限。每个登录账号在一个数据库中只能有一个用户账号。
- **继承规则三句**：用户继承所属角色的权限；用户分属多角色时权限基本取并集；只要有一个来源是 DENY，该权限即被拒绝。
- **与 D7（事务与 T-SQL 编程）混淆表**：

| 混淆点 | D8 安全管理 | D7 事务/T-SQL |
|---|---|---|
| 隔离级别 | 不是安全管理，是并发控制 | READ UNCOMMITTED 等四级 |
| 存储过程 | EXECUTE 属对象权限（D8） | 过程体语法、触发器（D7） |
| 备份还原 | ch11 后半，属容灾非权限管理 | 事务日志备份概念相邻但不混答 |

- **与 D1（完整性）区分**：完整性约束（主键/外键/CHECK）防"合法用户写入错误数据"；安全管理防"非法登录者与非授权用户"。都叫"保护数据"，防线不同——约束守数据内部，权限守数据门口。
- **教材存疑点**：书称"一般情况下任何用户都具有表或视图的读权限"——与 SQL Server 实际默认不符（public 不自动授 SELECT）。考试按教材表述，实操勿照搬。
