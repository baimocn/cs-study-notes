## A1 判词 · 第一处概念错误（NAME / FILENAME）
- **白墨答**：「name 指的是表名吧，filename 指的是文件名吧」→ **两处都错**
- **正确**：`NAME` = **逻辑文件名**（SQL Server 内部代号，与存放位置无关，出现在 sys.master_files / 备份文件 / RESTORE 的 MOVE 左侧）；`FILENAME` = **物理路径**（目录+文件名+扩展名，可搬动）
- **错型判定 = 「同名词撞车」造成混淆，不是概念没懂。** 根因：`NAME` 在 SQL Server 里极度重载 —— 在 `CREATE TABLE` 语境下常是表名/列名，在 `CREATE DATABASE … ON` 语境下却是**文件**逻辑名。他按"NAME＝名字＝表名"做了错误模式匹配
- **另一层漏掉**：`ON PRIMARY (…) / LOG ON (…)` 整段讲的是**文件存储**，**跟表毫无关系**
- **纠正手法（已交付图示）**：不直接给答案，先摆 `sys.master_files` 两列实证 —— 逻辑名 `自考题库_data` ≠ 物理名 `自考题库.mdf`（**两个名字根本不一样，这本身就推翻"NAME 是文件名"**）；再用「一个文件两个名字：代号 vs 住址」建模；最后落到 `RESTORE … WITH MOVE N'逻辑名' TO N'新路径'`（**搬家改住址、不改代号**），直通 D9
- **重要副产物（教学素材）**：**这条错误正是"抄过 ≠ 懂过"的现场证据** —— 他复制粘贴了建库脚本，库建对了、参数一个不错，但 `NAME` 的含义没进去；**复制粘贴不会报错，只会静默留下空洞**。且暴露得正是时候（比考场上暴露好）
- **留给他自己动手验证**（我不代跑）：`SELECT name AS 逻辑名, physical_name AS 物理路径 FROM sys.master_files WHERE database_id = DB_ID(N'自考题库');`
