# 00 · 工具上手卡（SQL Server 2025）

> 症状对应上一轮的第 1 类：**工具使用**。这一档归我 —— 下面每条命令我都在你机器上真跑过，不是抄文档。

## 一、先选路线：两条路，第一次走哪条？

| | SSMS（图形界面） | sqlcmd（命令行） |
|---|---|---|
| 适合 | **第一次上手**，边写边看 | **跑脚本文件**，稳、可复现 |
| 已装 | SSMS 22 + SSMS 20.2.1 + 中文包 | `sqlcmd.exe` 已在 PATH |
| 推荐 | ✅ **先用这个** | ✅ 脚本写完后用这个验一遍 |

**建议顺序**：SSMS 里把表建出来 → 存成 `.sql` 文件 → 再用 sqlcmd 跑一遍确认"从零也能跑通"。
因为任务卡要求脚本**能一次跑通**，而"在 SSMS 里点点点拼出来的表"≠"一个能跑的脚本"。

## 二、路线 A · SSMS（第一次走这条）

**1. 打开**：开始菜单搜 `SQL Server Management Studio`（22 或 20 都行）

**2. 连接**：
- 服务器名称：`localhost`
- 身份验证：**Windows 身份验证**
- 点连接

**⚠️ 如果报证书错误**（"证书链由不受信任的颁发机构颁发"）：
点开「选项 >>」→「连接属性」标签 → 勾上 **「信任服务器证书」** → 再连接。
> 命令行版本必须加 `-C`，这是同一个问题的两种表现。

**3. 写 SQL**：工具栏点「新建查询」（或 `Ctrl+N`）→ 出现一个空白页 → 直接打字

**4. 执行**：`F5`，或工具栏「执行」按钮
- 结果在下面 **「结果」** 标签页
- 报错在 **「消息」** 标签页

**5. 看成没成**：左侧「对象资源管理器」→ 右键「数据库」→ **刷新** → 你建的库就出现了
（**"刷新"这一步新手必漏**，不刷新会以为没建成）

**6. 存成交付文件**：
- `Ctrl+S` → 存到 `D:\Desktop\计算机科学与技术\造物-数据库\01-schema.sql`
- **保存对话框右下角「编码」→ 选「UTF-8 带签名」**
  > 因为你的脚本里一定有中文。UTF-8 不带签名时 SSMS 可能按 GBK 读，中文变乱码。

**7. 跑现成的文件**：文件 → 打开 → 文件 → 选中 `.sql` → `F5`

## 三、路线 B · sqlcmd（跑脚本文件，我实测过）

### 可用命令（照抄）

```bash
sqlcmd -S localhost -E -C -f 65001 -i "D:\Desktop\计算机科学与技术\造物-数据库\01-schema.sql"
```

### 每个参数为什么在这

| 参数 | 含义 | 能不能省 |
|---|---|---|
| `-S localhost` | 服务器 = 本机默认实例 | 可换 `(local)` |
| `-E` | Windows 身份验证 | 不省（免密码） |
| **`-C`** | **信任服务器证书** | **不能省** —— 省了直接连不上 |
| **`-f 65001`** | **输入文件按 UTF-8 读** | **不能省** —— 见下面踩坑记录 |
| `-i 文件` | 从这个文件读脚本 | 换成 `-Q "SQL"` 可直接跑一条 |

## 四、⚠️ 踩坑记录（我实测时真实发生的，你直接省掉）

### 坑 1 · 不加 `-C`

```
Sqlcmd: 错误: Microsoft ODBC Driver 18 for SQL Server : SSL 提供程序: 证书链是由不受信任的颁发机构颁发的。
Sqlcmd: 错误: ... 客户端无法建立连接。
```

→ 加 `-C` 即通。**（SSMS 里就是勾「信任服务器证书」）**

### 坑 2 · 不加 `-f 65001`（这个更狠）

同一个演练脚本，不加 `-f` 跑出来是这样：

```
宸插皢鏁版嵁搴撲笂涓嬫枃鏇存敼涓?"master"銆?
娑堟伅 102锛岀瓑绾?15锛岀姸鎬?1 ...
鈥?3013鈥濋檮杩戞湁璇硶閿欒銆?
```

**全部乱码 + 报语法错误。** 而且——**它真的在你机器上创建出了一个名字乱码的数据库**（我实测时发生了，事后已清掉，现在库里只剩 `master/tempdb/model/msdb/MySchool`）。

→ **含中文的 `.sql` 文件，`-f 65001` 不能省。**

### 加对了 `-f 65001` 之后，真实输出长这样

```

已将数据库上下文更改为 "_工具演练"。

(2 行受影响)
科目ID        科目代码  科目名称
----------- ----- ------------------------------
          1 13009 数据库原理与技术
          2 13013 高级语言程序设计
```

**这才是"通了"的样子。**

## 五、几个你一定会撞上的语法点

**1. 中文/Unicode 字符串要加 `N` 前缀**
```sql
INSERT INTO 科目(科目代码, 科目名称) VALUES ('13009', N'数据库原理与技术');
--                                               ↑ 这个 N 不加，中文可能存成问号
```

**2. `GO` 是什么**
它不是 SQL 语句，是 **sqlcmd / SSMS 的"分批执行"分隔符**。SQL Server 引擎本身不认识它。
作用：告诉工具"前面这段先发过去执行"。

**3. 为什么任务卡要求先 `USE master`**
因为 `CREATE DATABASE` **不能和它后面的语句放在同一批里**。正确姿势：
```sql
USE master;
GO
CREATE DATABASE 你的库名;
GO
USE 你的库名;
GO
-- 从这里开始建表
```
`GO` 把"建库"和"进库"切成两批，否则报错。

**4. 我已经建好的演练脚本**
`造物-数据库\00-演练脚本.sql` —— **它不是 A1 的答案**，只干一件事：让你在 5 分钟内亲眼看到"从文件到表里出现数据"的完整闭环。
它自建自用，跑完可以 `DROP DATABASE [_工具演练]` 清掉。

**建议你先跑这一个。跑通了，A1 就只剩下"设计"这一件事，不再有"工具"这一件事。**

## 六、跑通了怎么算"跑通"

顺序上，你能一眼回答这四个"是"：

1. `01-schema.sql` 双击用 SSMS 打开 → `F5` → **消息窗没有红色**
2. 对象资源管理器刷新后，能看到**你建的库**，展开能看到**你建的表**
3. 命令行再跑一遍同样的文件（带 `-C -f 65001`）→ **也是零报错**
4. 表里能查出数据

第 3 条最容易被跳过，但它才是任务卡要的"一次跑通" —— **在别人机器上从零开始也能跑通，才叫脚本。**

## 七、桌上那个 DB Browser (SQLite) —— 不要拿它做这门课

**结论先给：A1 用 SSMS 22（你桌面就有它的快捷方式），不要用 DB Browser。**

不是它不好，是**它不是这门课的工具**。SQLite 和 SQL Server 是两种不同的 SQL 方言，而你的考卷写的是 **T-SQL**。

### 具体差在哪（每条都直接影响你）

| 点 | SQL Server（**要考这个**） | SQLite（DB Browser） |
|---|---|---|
| 类型系统 | **静态强类型**，写错直接报错 | 动态类型 / 类型亲和 —— **字符串能塞进 INT 列** |
| 类型名 | CHAR / VARCHAR / NVARCHAR / DATETIME / BIT / DECIMAL | 只有 5 种：NULL / INTEGER / REAL / TEXT / BLOB |
| 自增 | `IDENTITY(1,1)` | `INTEGER PRIMARY KEY AUTOINCREMENT` |
| 取前 N 行 | `SELECT TOP 10 …` | `LIMIT 10` ← **考试写这个直接错** |
| 拼字符串 | `+` | `||` |
| 当前时间 | `GETDATE()` | `date('now')` |
| 外键 | 写了就强制 | **默认不强制**，要 `PRAGMA foreign_keys = ON` |
| `GO` | 认（工具分批符） | **不认** |

### 更要命：D7、D8、D9 三章在 SQLite 里根本练不了

- **D7 事务与 T-SQL 编程** —— T-SQL 是 SQL Server 的方言，SQLite 没有这一套
- **D8 安全管理** —— SQLite **没有用户和权限概念**（它靠文件权限），练不了
- **D9 备份还原与导入导出** —— SQLite 是"复制那个 `.db` 文件"，跟 SQL Server 的备份/还原完全是两回事

### 还有一个直接的坑

A1 硬性要求第 3 条是"外键约束"，第 7 条是"数据类型选得有理由"。
**在 SQLite 里，这两条你写了也可能根本不生效** —— 外键默认不拦、类型随便塞。
→ 你会以为自己写对了，其实是工具没检查你。**这种"假通过"比直接报错危险得多。**

### 那它有什么用

- **概念层是通的**：SELECT / WHERE / JOIN / GROUP BY 的思路两边一样，学到的不浪费
- 轻、单文件、不用连服务 —— 适合随手看小数据，或用在别的项目里
- **但它不是这门课的工具。**

### 如果你只是嫌 SSMS 重

那要换的是 **sqlcmd**，不是 SQLite：

```
sqlcmd -S localhost -E -C -f 65001 -i "你的脚本.sql"
```

一条命令、没有界面、比 SSMS 轻得多，而且**方言是同一个**。

## 八、建库三件事：库名 · 用「新建查询」· 指定文件夹

### 1 · 库名叫什么

**建议 `自考题库`。** 理由就两条：和 `MySchool` 一眼分开；够短。
建完再改库名很麻烦（要分离/附加），所以**一次定好**。中文库名没问题，只是引用时要带方括号 —— `USE [自考题库]`。

### 2 · 「新建查询」连的是哪个库？（新手第一个困惑）

**「新建查询」只是开一个写字窗口。它连的是你当前在对象资源管理器里选中的那个库**，默认落在 `master`。

**所以：新库还不存在，你不需要"先连上它"。就在 `master` 里敲 `CREATE DATABASE`。**

步骤：

1. 左侧对象资源管理器 → 展开「数据库」（能看到 master / MySchool…）
2. 工具栏「新建查询」（`Ctrl+N`）→ 出现空白窗口
3. **看一眼窗口右上角那个数据库下拉框**，确认是 `master`
4. 在窗口里写下面的脚本 → `F5`
5. 回左侧，右键「数据库」→ **刷新** → `自考题库` 出现了

### ⚠️ 不要用「数据库 → 右键 → 新建数据库」那个图形向导

它也能建库，但**建完不留脚本**。任务卡要的是"一个能一次跑通的 `01-schema.sql`" —— 向导点出来的东西**不是脚本**。

### 3 · 数据文件放哪个文件夹

**放这儿**（目录已经建好，我也实测过）：
```
D:\Desktop\计算机科学与技术\造物-数据库\db\
```
好处：**数据库文件就躺在你的项目里** —— A4 备份还原时你直接看得见 `.mdf` / `.ldf`，D9 那章"数据库在磁盘上长什么样"不用讲，你自己会看见。

**⚠️ 必踩的坑：文件夹必须先存在。**
SQL Server **不会**替你建目录。目录不存在会报「操作系统错误 3(系统找不到指定的路径)」之类。
→ 先在资源管理器里把 `db` 文件夹建出来，**再**执行建库语句。

### 4 · 完整建库脚本（照抄，只需确认库名）

```sql
USE master;
GO

-- “不存在才建”：脚本可以反复跑，不会删掉你已经有的数据
IF DB_ID(N'自考题库') IS NULL
BEGIN
    CREATE DATABASE [自考题库]
    ON PRIMARY (
        NAME       = N'自考题库_data',
        FILENAME   = N'D:\Desktop\计算机科学与技术\造物-数据库\db\自考题库.mdf',
        SIZE       = 8MB,
        MAXSIZE    = 200MB,
        FILEGROWTH = 8MB
    )
    LOG ON (
        NAME       = N'自考题库_log',
        FILENAME   = N'D:\Desktop\计算机科学与技术\造物-数据库\db\自考题库_log.ldf',
        SIZE       = 8MB,
        MAXSIZE    = 100MB,
        FILEGROWTH = 8MB
    );
END
GO

-- 让这个库的语法行为贴近考试的 2012 口径
ALTER DATABASE [自考题库] SET COMPATIBILITY_LEVEL = 110;
GO
```

### 参数是什么意思

| 参数 | 意思 |
|---|---|
| `NAME` | 这个**文件**的逻辑名（**不是库名**，最容易混） |
| `FILENAME` | 文件落在磁盘的**完整路径**（含文件名和扩展名） |
| `SIZE` | 初始大小 |
| `MAXSIZE` | 上限（不写＝不限，练习库够用） |
| `FILEGROWTH` | 装满了每次扩多少 |
| `ON PRIMARY` | 数据文件（`.mdf`） |
| `LOG ON` | 日志文件（`.ldf`） |

### 为什么用「不存在才建」而不是 `DROP DATABASE`

任务卡要求脚本能一次跑通，而你以后会**反复跑**它。
- 写成 `IF DB_ID(...) IS NULL` → 重复执行不动你已有数据 ✅
- 写成开头 `DROP DATABASE` → **跑第二次你数据就没了** ❌

### 5 · 我实测的结果（你照做就是这个结果）

我用**同一套语法、同一个目录**试过一次（临时库名，跑完已删干净）：

```
db\...mdf        8,192 KB
db\...ldf        8,192 KB
```

两个文件**真的出现在那个目录里**。
另外顺手验证了：**兼容级别 110（= SQL Server 2012）在你这台 2025 上是可设的**（读完回读确认＝110）。这条之前标着"待验证"，现在结了。

### 6 · 这两个文件是什么

- **`.mdf`** = 数据文件 —— 你的表和记录实际存这儿
- **`.ldf`** = 日志文件 —— 事务日志，**D7 事务那一章的核心对象**

**它们就是你 A4"亲手改坏再修好"和 D9"备份还原"的实物。** 先记住它们长什么样、在哪。

### 7 · 补：`NAME` 到底是什么（一个反例实验）

**先破三个误会**：`NAME` **不是**表名，**不是**文件名，**也不是**从后缀推出来的。它是**你自己起的一个代号**。

我做过一个反例：建库时故意写 `NAME = N'香蕉'`、`NAME = N'西瓜'`，而文件叫别的名字。结果：

```
逻辑名   类型   物理路径
香蕉     ROWS   D:\SQLData\_演示_名字跟文件名无关.mdf
西瓜     LOG    D:\SQLData\_演示_名字跟文件名无关_log.ldf
```

**两个名字毫无关系。** 逻辑名跟文件名、后缀、路径**全都不相干**。

| | 是什么 | 类比 |
|---|---|---|
| **`NAME`** | 逻辑名 = **代号**，跟文件放哪无关 | 像 C 里的变量名 `int a = 5;` —— `a` 跟 5 存在哪个地址没关系 |
| **`FILENAME`** | 物理路径 = **住址**（目录+文件名+扩展名），可以搬 | 搬家会变的那串地址 |

**它的用处**：给 SQL Server 一个"**跟位置无关**"的方式去指代同一个文件——

- 换位置：`ALTER DATABASE … MODIFY FILE (NAME = N'逻辑名', FILENAME = N'新路径')`
- 从备份还原到别处：`RESTORE … WITH MOVE N'逻辑名' TO N'新路径'` ← **D9 要考的就是这个**

> **关键一句：逻辑名不是"判断"出来的，是"起"出来的。**
> 叫什么由建库的人决定。你上次那串 `自考题库_data` 是照抄我模板的 —— 所以你从来没机会看见"这名字从哪来"，它才显得凭空冒出来。
