# D9 备份还原与数据导入导出（SQL Server 2012 · ch11 §11.4-11.9）

> 单元性质：D8 边界淘汰内容的补位收编（D8 verified.md X1/X2）；覆盖 ch11 练习题 4-7。

## R 引用（OCR 已修，≤150 字）

> 「SQL Server 2012 中把备份分为两大类：数据库备份、文件和文件组备份。数据库备份又分为完整、差异、事务日志。……差异备份是指将最近一次数据库备份以来发生的数据变化备份起来，因此，差异备份实际上是一种增量数据库备份。……在使用事务日志对数据库进行还原操作时，还必须有一个完整的数据库备份，而且事务日志备份还原时必须按一定的顺序进行。」

—— ch11 §11.4.2（约 30 字删节；OCR 修复见文末审计）

## I 骨架 + 钩子

### 知识骨架（六块）

1. **概念对偶**（§11.4.1）
   - 备份=制作数据库结构、对象和数据的复制（为修复）；还原=将备份加载到服务器的过程（为恢复）。
   - 还原状态由备份决定；备份中未完成的事务不还原。
   - 需要备份还原的四种情况：存储媒体损坏 / 用户操作错误 / 服务器崩溃 / 服务器间移动数据库。
2. **四种备份类型**（§11.4.2）——本单元主干，一个都不能少：
   - 完整备份：所有数据+数据库对象；慢、占空间；常安排在晚间；从备份开始到还原开始之间的修改无法还原。
   - 差异备份：最近一次**数据库备份**以来发生的变化；=增量备份；量小、快；不能到失败点。
   - 事务日志备份：上次日志/差异/完全备份之后所有**已完成的事务**；量最小；可到失败前一点；依赖完整备份+顺序重放。
   - 文件或文件组备份：只备某个文件/文件组；只还原损坏部分故还原快；**必须再配事务日志备份**否则其中变化无效。
3. **三种恢复模式**（§11.4.3）
   - 简单还原 Simple：只用数据库/差异备份→只能回到上一次备份状态；配方=完整+差异。
   - 完全还原 Full：数据库备份+日志备份→还原到失败时刻，几乎不丢数据；配方=完整+差异+日志。
   - 批日志还原 Bulk-logged：减少批操作（SELECT INTO、批装载、建索引、WRITETEXT/UPDATETEXT）日志空间；配方同完全。
4. **还原链**（§11.4.2/§11.4.3）
   - 顺序铁律：最近完整备份→最近差异备份→依序各日志备份（含失败前抢出的活动日志尾）。
   - 抢不到日志尾→只能还原到最后一次日志备份状态，非失败点。
5. **操作与设备**（§11.5）
   - 备份设备=存储介质（硬盘/磁带/管道；本地磁盘文件时无需专门建设备）；先建设备再备份。
   - T-SQL 用 BACKUP DATABASE / RESTORE DATABASE；SSMS 走"任务→备份 / 任务→还原"。
   - 系统数据库：定期备份 master、msdb、model；tempdb 不可备份（启动重建、关闭清空）。
   - 自动定时备份=维护计划（仅企业版有）；备份期间禁做：建删数据库文件、建索引、非日志操作、收缩库。
6. **导入导出**（§11.9）
   - SSMS 右键库→任务→导入数据/导出数据→"导入和导出向导"：定源→定目标→选表或写查询→列映射→执行。
   - 支持多种数据库和文件（Access、MySQL、Excel…）；导入时源表结构须与库中表结构一致，否则在"列映射"里改。

### 钩子（本单元记两套）

- **摄影四兄弟**：**完整=全家福**（数据+对象全拍）；**差异=只拍新来的**（上次全家福之后新进的变化，基准是最近一次完整备份）；**日志=监控录像**（记录动作，可逐帧回放到失败点）；**文件组=按房间拍**（单间受损单间修，但须配监控录像保证一致）。
- **放映铁律**：**还原必须从全家福开始放**——先放最近一张全家福（完整），再放最近的"新来的"合集（差异，只需最近一份），最后按时间顺序连放监控录像（日志，一环不跳）；崩溃瞬间先抢出最后一段监控（活动日志尾）再放映。
- 备份 vs 导入导出：**备份是自救**（.bak 只能被 RESTORE 读），**导入导出是外交**（.xls 谁都能读）。

### 四类型速查表（填空/选择弹药，先答类型再答特性）

| 类型 | 备份什么 | 速度/体积 | 能否到失败点 | 前提/配套 |
|---|---|---|---|---|
| 完整 | 所有数据+数据库对象 | 最慢/最大 | 不能（只能到备份时刻） | 无（是链条底座） |
| 差异 | 最近一次完整备份以来的变化 | 快/较小 | 不能 | 必须先有完整备份 |
| 事务日志 | 上次日志/差异/完整备份后已完成的事务 | 最快/最小 | 能（按顺序重放+日志尾） | 必须先有完整备份+按序重放 |
| 文件/文件组 | 指定文件或文件组 | 只备局部 | 单文件级修复 | 备完须再做日志备份 |

### 三种恢复模式速查表（练习题 6 弹药）

| 模式 | 英文 | 备份配方 | 能回到哪 |
|---|---|---|---|
| 简单还原 | Simple Recovery | 完整+差异 | 上一次备份时刻（回不到失败点） |
| 完全还原 | Full Recovery | 完整+差异+日志 | 失败时刻（几乎不丢数据，需日志尾） |
| 批日志还原 | Bulk-logged Recovery | 同完全 | 同完全；特长=省批操作日志空间 |

### 综合方案速记（§11.4.2 标准配方）

- 节拍：**完整备份（每晚）→ 差异备份（每 3~4 小时）→ 日志备份（每 10~30 分钟）**；三层节拍越密，回放粒度越细、丢失越少。
- 换算口诀：层级每降一级，间隔缩一档、体积小一档——全家福少拍，新来的勤拍，录像常转。

## A1 书中例题（备份 / 还原 / 导入导出各一）

**例 1·备份配方（§11.4.2 综合方案）**：要最大限度减少还原时间与数据损失——有规律完整备份（每晚）→较短间隔差异备份（3~4 小时）→相邻差异之间日志备份（10~30 分钟）。结论：三类备份叠加是标准配方，差异与日志都挂在完整备份链上。

**例 2·还原到失败点（§11.4.2 四步 + §11.8 案例）**：student 库更新慢、量不大→维护计划每周日 0:00 完整备份（仅企业版可用维护计划）；崩溃时若日志可访问：先备份活动事务日志→还原最近完整备份→还原最近差异备份→依序还原其后日志备份。结论：顺序错=还原失败；无法备份活动日志则止步于最后一次日志备份。

**例 3·导出 Excel（§11.9）**：右键 student 库→任务→导出数据→源选 SQL Server Native Client 11.0+student 库→目标选 Microsoft Excel（D:\stu.xls）→选"复制一个或多个表或视图的数据"→勾"学生"表（可编辑列映射）→执行成功（"已传输 10 行"）。结论：导入导出=源→目标搬运；导入反过来走，且源表结构必须与库中表结构一致。

**补充语法帧（教材未给出，标准语义标注为补充，考题若考照此作答）**：
```sql
BACKUP DATABASE student TO studentbak        -- studentbak=备份设备名；差异加 WITH DIFFERENTIAL；日志用 BACKUP LOG
RESTORE DATABASE student FROM studentbak     -- 日志用 RESTORE LOG ... WITH NORECOVERY（链未完）/ WITH RECOVERY（收尾）
```

## A2 触发题型★

| 题型 | 信号词 | 作答要点 |
|---|---|---|
| 填空/简答 | "数据备份的类型""有哪几种""增量备份" | 四种：完整（所有数据+对象）、差异（最近一次数据库备份以来的变化=增量）、事务日志（上次备份后已完成的事务）、文件或文件组；各自适合的库：完整→变化不频繁/可容忍丢失，差异→量小求快，日志→不许丢数据/可还原到失败点/库变化频繁，文件组→超大数据只修坏文件 |
| 简答 | "恢复方式""还原模式""Simple/Full/Bulk-logged" | 三种：简单（完整+差异，回不到失败点）、完全（完整+差异+日志，到失败时刻）、批日志（配方同完全，省批操作日志空间） |
| 选择 | "还原时第一步""首先应该做什么""还原顺序" | 第一步：先还原最近一次**完整**数据库备份（若日志可访问，更前置一步是先备份当前活动事务日志）；随后最近差异→依序日志 |
| 应用 | "每周X完全备份每天差异每小时日志，X时X分崩溃""损失最小" | 套 E 步骤：判模式→排链→答顺序（见 E 与 A1 例 2） |
| 选择/判断 | "tempdb""master/msdb/model""备份设备" | 定期备份 master/msdb/model 三个；tempdb 不可备份（启动重建、关闭清空） |
| 简答/判断 | "导出数据""导入数据""Excel""列映射" | 导入导出向导定源定目标搬数据；导入须源表结构与库中一致，否则在列映射中设置；.bak 只能还原、.xls 可直接打开 |
| 判断 | "备份过程中""在线备份" | 支持在线备份；期间禁止：建删数据库文件、创建索引、非日志操作、收缩数据库；中断可从断点继续 |

## E 考场步骤：备份还原题作答三步（先判→再排→后答）

1. **判恢复模式**：题面要"还原到失败点/不丢数据"→完全（或批日志）模式，配方含日志备份；题面只说"定期备份"→简单模式即可，配方=完整+差异。
2. **排备份链**：把题面给的备份按时间轴铺开——完整（基准）→差异（取崩溃前最近一份）→日志（取差异之后的依序列表，**不要**取差异之前的）。
3. **答操作序列**：按固定句式输出：①（日志文件可访问时）备份当前活动事务日志；②还原最近一次完整备份；③还原最近一次差异备份；④按时间顺序还原其后各次日志备份（可写"最后应用日志尾前滚到失败时刻"）。若题面说日志文件已损坏→注明"无法备份活动日志，只能还原到最后一次日志备份状态"。
   - **判停条件**：题面只问"备份类型/恢复方式是哪几种"→第 1 步答完即停，勿展开还原序列；题面给了具体备份时间表→必须走满第 3 步并逐一点名时间点（漏点时间=丢步骤分）。
   - **导入导出题判停**：只答"向导定源定目标+产物形式+结构一致/列映射"三句，不展开向导逐击。

## B 边界★（失分点与混淆表）

- **差异备份必须先有完整备份**：差异只记"相对最近一次完整备份的变化"，无完整备份则差异成为无基之量、无法还原。
- **日志备份不能单独恢复**：日志还原必须先有完整备份打底，且各次日志须按备份顺序重放；跳序、颠倒、无打底均失败。
- **备份≠复制文件**：完整备份是"先将事务日志写到磁盘上，再根据事务重建数据库/对象并复制数据"的一致性过程；还原时未完成事务不还原。直接拷 mdf/ldf 不等于备份（教材未明写此对比，为标准语义补充，防实操性误解）。
- **抢日志尾是最易漏的一步**：还原到失败点的第一步不是"还原完整备份"，而是（日志可访问时）先备份当前活动事务日志。
- **与 D8（安全管理）混淆表**：

| 混淆点 | D9 备份还原 | D8 安全管理 |
|---|---|---|
| "保护数据"的防线 | 事后容灾：坏了能恢复 | 事前门禁：防非法访问 |
| BACKUP DATABASE | 一条**备份语句**（本单元） | 一项**语句权限**（授权谁可执行） |
| 权限问题 | 不答：授权/角色/验证模式归 D8 | — |

- **与 D7（事务）混淆表——两个"事务日志"不是一回事**：

| 混淆点 | D9 | D7 |
|---|---|---|
| 事务日志（文件/内容） | 被备份的**对象**：.ldf 里记录的事务记录 | 事务机制本体：BEGIN/COMMIT/ROLLBACK、ACID |
| 事务日志备份 | 一种备份**类型**（本单元核心） | 不是 D7 概念，勿混答 |
| 日志的作用 | 还原时按顺序重放以恢复到失败点 | 保证事务原子性/持久性的底层机制 |

- **三对易混辨析**：完整 vs 差异=变化基准（完整无基准、差异以最近完整为基准）；差异 vs 日志=记"状态快照差" vs 记"动作流"（日志可回放到失败点，差异不能）；恢复模式 vs 备份类型=能力承诺（能回到哪）vs 原材料（拿什么回）。
- **教材存疑点**：①§11.9 称导入导出"只在企业版或开发版才有、须装 SP1"——与实际不符，考试按教材答；②"批日志还原性能优于简单还原和完全还原"表述过强，其优势仅限减少批操作日志空间；③SQL Server 2012 实际支持备份到网络介质，教材"只支持本地磁带机"为陈旧表述——均按教材表述应试、实操勿照搬。
