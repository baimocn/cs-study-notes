# D1 关系模型与完整性

## R 原文

> "数据完整性是指关系模型中数据的正确性与一致性。关系模型允许定义三类完整性约束：实体完整性约束、参照完整性约束和用户自定义完整性约束。"——ch01 §1.2.1（OCR"亢余"类坏字已修）

> "数据完整性是指数据的精确性（Accuracy）和可靠性（Reliability）。……数据完整性被分为四类完整性：实体完整性、域完整性、参照完整性、用户定义的完整性。"——ch07 §7.1

> "使用约束优先于使用触发器、规则和默认值。"——ch07 §7.2

## I 骨架

**背景一句**：数据管理经历人工管理→文件系统→数据库系统三阶段；数据库系统靠三级模式两级映像组织数据（阶段名称可考填空，年代不背）。

**钩子1 · 四类完整性 = "行、格、表、人"**：
- 实体完整性管**行**：行行有身份证（主键非空且不重复）。
- 域完整性管**格**：格格有门槛（类型、范围、非空）。
- 参照完整性管**表与表**：表表有户口（从表引用的值，主表必须真有）。
- 用户定义完整性管**人**：剩下的规矩用户自己定（其余三类都能承载它）。

**钩子2 · 六约束对号入座**："主键锁行，UNIQUE 锁列放空行，CHECK 划红线，DEFAULT 填空位，NOT NULL 堵空洞，外键认亲戚。"
- PRIMARY KEY：唯一+非空，每表都应有一个；无自然键就用整数序列。
- UNIQUE：列内不重复，但**允许空值**——这是它与主键的唯一分界线。
- CHECK：布尔条件，拒绝非 TRUE 值；一个字段可挂**多个** CHECK。
- DEFAULT：没填就自动补默认值。NOT NULL：不许空。
- FOREIGN KEY：本表的列不是本表主键，却指向别表的主键/候选键。

**钩子3 · 参照三禁 = "插、删、改三个方向都不放行"**：
禁从表插入主表没有的键值；禁删除从表有对应记录的主表行；禁把主表被参照键改成从表对不上的值。

**钩子4 · 主表从表 = "键的老家是主表，借用的地方是从表"**：
属性在 A 表当主键（老家）→A 是主表；同一属性在 B 表当外键（借用）→B 是从表。例：学生(学号…)主表，选课(学号…)从表。

**钩子5 · 开销阶梯 = "杀鸡别用牛刀"**：
数据类型（最低）→ 默认/规则 → 约束 → 触发器（最强最贵）。**能用约束就不用触发器，能用数据类型就不用规则**。

**钩子6 · 规则/默认对象生命周期 = "先结绑再扔"**：
创建→绑定→解绑→删除；DROP 前必须先解绑，否则删不掉。区别于约束：规则/默认对象独立于表、一次定义多处绑定；一个字段只能绑**一个**规则（CHECK 可多个）。

**钩子7 · 范式升级链 = "1 拆原子，2 拆部分，3 断传递，BC 管主属性，4 斩多值"**：
1NF 属性不可分；2NF 消除非主属性对码的**部分**依赖；3NF 消除**传递**依赖；BCNF 要求每个决定因素都含码；4NF 消除非平凡且非函数依赖的**多值**依赖。规范化=分解="单一化"：一个关系表示一事或一物。

**钩子8 · 三级模式 = "外看、中管、内存"**：
外模式（=子模式=用户模式，可多个，安全屏障）；模式（=逻辑模式，仅一个，全局逻辑）；内模式（=存储模式，仅一个，物理存储）。外模式/模式映像保**逻辑**独立性；模式/内模式映像保**物理**独立性。口诀：映像夹住的两层变了→上层不动=独立。

**钩子9 · E-R 转主键 = "1:1 随便放，1:n 放 n 端，m:n 组合上"**：
1:1 可独立可并入任一端；1:n 并入 n 端、键取 n 端键；m:n 必须独立成表、键=两端键的组合。

**钩子10 · 函数依赖看语义**：依赖是"语义"定的，不是算出来的——允许重名，姓名→年龄就塌。

## A1 教材实例

1. **合一表之祸**（ch01 §1.2.2）：学生-选课-课程合成一张表，主键(学号,课程号)。问题→规则→结论：①新课没人选→学号空→**实体完整性拒绝插入**（插入异常）；②删光某生选课记录→该生信息跟着消失（删除异常）；③改姓名只改到一半元组（修改异常）；④学生细节反复存（冗余）。拆成学生/课程/选课三表全消，代价是跨表连接查询开销变大。
2. **判 2NF**（ch01 §1.2.2）：选课1(学号,课程号,系部代码,出生日期,成绩)——系部代码、出生日期只依赖学号（部分依赖）→不满足 2NF→分解为选课(学号,课程号,成绩)+学生。
3. **判 3NF**（ch01 §1.2.2）：学生2(学号,…,系名,系宿舍楼)——学号→系名→系宿舍楼（传递）→分解出宿舍楼(系名,系宿舍楼)。
4. **判 BCNF**（ch01 §1.2.2）：教学(学生,教师,课程)——教师是决定因素却不含码→不属于 BCNF。
5. **约束落地**（ch07 §7.3）：例7.4 学分 CHECK(学分 BETWEEN 1 AND 7)；例7.5 入学时间 CHECK(>'1978-01-01' AND <GETDATE())；例7.6 注册时间 DEFAULT GETDATE()；例7.7 学历 DEFAULT '本科'；例7.8 班级.专业代码 FOREIGN KEY REFERENCES 专业(专业代码)。
6. **规则绑定**（ch07 §7.6）：CREATE RULE xb_rule AS @xb IN('男','女')，再 sp_bindrule 绑到'学生.性别'。
7. **E-R 落地**（ch01 §1.1.4）：学生-课程是 m:n（一生多课、一课多生）→选课表键=(学号,课程号)；课程-教材是 1:1（一门课只用一种教材）→可并入任一端。
8. **唯一约束落地**（ch07 §7.3.2 例7.3）：系部表主键是系部代码，但系部名称也要唯一→为书号/系部名称建 UNIQUE 约束（uk_sh），与主键并存互不冲突。

## A2 触发题型★

- **填空**：信号词"唯一标识元组的属性（或属性组合）"→候选码/主码；"关系模型由___、___、___组成"→数据结构/关系操作/数据完整性；"三级模式"→外模式/模式/内模式；"六类约束"→NOT NULL/CHECK/UNIQUE/PRIMARY KEY/FOREIGN KEY/DEFAULT；"数据完整性分为___类"→四类。
- **简答**：信号词"什么是数据完整性/分为哪几种"→四类+含义+对应约束（ch07 习题1/2 原题）；"参照完整性作用"→三禁；"规则与 CHECK 约束区别"→一字段一规则 vs 多 CHECK、独立创建可复用 vs 随表建；"什么是规范化"→单一化、一事一物。
- **判断**：信号词"UNIQUE 约束的字段不允许空值"→**错**（主键才非空）；"一个字段可应用多个规则"→**错**（CHECK 才可以）；"视图属于外模式"→对；"删除规则可直接 DROP"→**错**（先解绑）；"主键约束优先于 UNIQUE 索引"→对。
- **应用**：信号词"给出关系模式，判定范式级别并分解""指出主键/外键""该建什么约束"。

## E 考场步骤

1. **先认题型**：见"完整性/约束"字样→走归类；见"范式/依赖"→走升级链；见"模式/独立性"→走三级模式。
2. **归类题**：问自己四连——这规矩管"行唯一"吗（实体）？管"格子取值"吗（域）？管"表间引用"吗（参照）？都不是→用户定义。再映射约束：行→PRIMARY KEY/IDENTITY，格→CHECK/DEFAULT/NOT NULL，表间→FOREIGN KEY。
3. **约束选型题**：先问"允不允许空"→非空唯一选主键、可空唯一选 UNIQUE；再问"管几个字段"→多字段必须表约束。
4. **范式题**：①找码→②查非主属性对码是部分还是完全→部分依赖卡在 1NF→2NF；③查传递依赖→有则卡 2NF 不到 3NF；④查决定因素是否都含码→BCNF；⑤有多值依赖→4NF。
5. **判停条件**：题目只问级别不问分解→答到级别即停；问"实现方法"→约束名+一句作用即停；分析异常→必须点出"违反了哪条完整性规则"才收笔。

## 术语速查（名词解释/填空直取）

- **实体/属性/域**（ch01 §1.1.4）：客观存在可相互区别的事物=实体；实体所具有的特性=属性；属性的取值范围=域（性别域={男,女}）。实体型=实体名+属性名集合；实体集=同型实体集合。
- **候选码/主码/外键**（ch01 §1.2.1）：能唯一标识元组的属性（组）=关键字/码；多个都能唯一标识→都是候选码，从中指定一个=主码；不是本表的码（或只是码的一部分）却是另一关系的码→外键。
- **关系模式/元组**（ch01 §1.2.1）：二维表的列=属性、列值取值范围=值域；行定义（型）=关系模式；行（值）=元组，元组的集合=关系；不能组成关键字的属性=非主属性。
- **E-R 图符号**（ch01 §1.1.4）：矩形=实体型，椭圆=属性，菱形=联系；联系也可以有属性（如"选课"联系带"成绩"）。
- **四种结构数据模型**（ch01 §1.1.4）：层次、网状、关系、面向对象；关系模型三优点：数学基础严格、概念单一（实体和联系都用关系表示）、存取路径对用户透明。
- **DDL/DML**（ch01 §1.1.3）：数据定义语言（CREATE/ALTER/DROP 类）／数据操纵语言（增删改查）。
- **外模式别名**（ch01 §1.1.5）：外模式又称子模式、用户模式；模式又称逻辑模式；内模式又称存储模式——别名换着考。

## B 边界★

**勿用场景（反例陷阱）**：
- 别把"UNIQUE=主键"：UNIQUE 允空、主键不允许；主键约束优先于 UNIQUE 索引。
- 别把 CHECK 和规则混用：一字段多 CHECK 可以，多规则不行；规则要先绑定才生效。
- 别用触发器做简单完整性：多表级联等复杂逻辑才上触发器，简单约束场景触发器是开销浪费。
- 别把外键当本表主键：外键"不应该是该表的主键"，它指向别表的主键/候选键。

**教材警告的失败模式**：
- 表中已有重复数据→设主键直接报错（须先清理，ch07 §7.3.1）。
- 已有数据与 CHECK 条件冲突→约束创建失败（ch07 §7.3.3）。
- 主从表数据有矛盾→外键关系保存失败，先整理数据再建关系（ch07 §7.3.5）。
- 外键涉及多列：一个约束含一个以上字段必须用**表约束**形式（ch07 §7.2）。
