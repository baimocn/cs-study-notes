# 这册蒸馏在讲什么

这套教材的知识体系是一条从"概念"到"治理"的单行道。

先用关系模型回答"数据该长什么样"——实体、码、四类完整性、范式、三级模式（D1）；
再用 DDL 让它落地成真正的文件和表——CREATE DATABASE/TABLE、数据类型选型（D2）。
表有了，接下来是两大查询命门——单表 SELECT 的五子句与执行顺序（D3），
以及把多张表拼起来的连接家族（D4）。
数据能查还要查得快、看得清爽，于是有了索引与视图这对"空间换时间、定义换简洁"的抽象工具（D5）。
算术交给内置函数（D6），编程交给 T-SQL 与事务（D7），
最后是治理层：谁能进、能干什么是安全管理（D8），坏了怎么办是备份还原（D9）。

概念、结构、查询、优化、函数、编程、治理——七个论点拎完，一本书的骨架就完整了。

每个单元的 SKILL.md 是"单兵作战手册"，而这册 DIGEST 是"集团军作战图"。

使用方式：先在这里用方法论小节建立判据直觉——每节五拍（解决什么问题 / 核心逻辑 / 一例 / 何时失效 / 深入链接），五分钟过完一个武器库。
发现哪个判据手感生疏，顺末尾的链接跳回对应单元的 SKILL.md 看全量例题与题型清单。
它不替代刷题，替代的是刷题前的那遍"把刀磨齐"。

本册的剪裁标准只有一条：能不能构成失分点。

所有钩子、判据、反例都从九个单元的 verified 链路（候选→验证→蒸馏）里筛出来，
教材存疑的地方明确标注"考试口径"，不假夸、不注水。
考前最后一晚，你只需要这册的最后三节。

## 一、概念地基：关系模型是所有题的裁判规则（D1）

### 方法论 1：四类完整性归类四连问

- **它解决什么问题**：简答判断题最爱问"这条规矩属于哪类完整性？该用哪个约束？"——归类错，后面全错。
- **核心逻辑**：
  - 一问管"行唯一"吗？→ 实体完整性（主键非空且不重复）。
  - 二问管"格子取值"吗？→ 域完整性（类型、范围 CHECK、DEFAULT、NOT NULL）。
  - 三问管"表间引用"吗？→ 参照完整性（外键：从表引用的值主表必须真有）。
  - 都不是 → 用户定义完整性（前三个壳都装得下它）。
  - 口诀："行、格、表、人"四字收完全部规矩。
  - 注意口径差：ch01 说"三类完整性"、ch07 说"四类"（把用户定义拆出来单列）——填空按题面对应章节口径答。
- **书中用法**：`ALTER TABLE 学生 ADD CHECK(性别 IN('男','女'))` ——性别取值门槛题，判据是"格格有门槛"，归域完整性。
- **何时失效**：题目不问归类只问"怎么写"（DDL 语法）时，别绕回概念层——那是 D2 的地盘。

→ 深入请读 D1-关系模型与完整性\SKILL.md

### 方法论 2：参照三禁与主从表判定

- **它解决什么问题**：外键题三连——谁是主表谁是从表？哪种插入/删除/修改会被拒？为什么外键建不起来？
- **核心逻辑**：
  - 键的老家是主表，借用的地方是从表：学号在学生表是主键 → 学生是主表；同一学号用在选课表 → 选课是从表。
  - 三禁：禁从表插入主表没有的键值；禁删除从表仍有对应记录的主表行；禁把主表被参照键改成从表对不上的值。
  - 外键"不应该是本表的主键"——它指向别表的主键/候选键。
- **书中用法**：学生(学号…) 主表、选课(学号…) 从表：删除选课记录无害，删除学生记录被禁。
- **附带判据**：约束选型两问——先问"允不允许空"（非空唯一选主键，可空唯一选 UNIQUE）；再问"管几个字段"（一个以上字段必须表约束形式）。
- **何时失效**：建外键报错时，先查主从表数据有没有矛盾、被引用列是不是主键——约束建不起来的失败模式都出在这两处。

→ 深入请读 D1-关系模型与完整性\SKILL.md

### 方法论 3：范式升级链一级一级找病因

- **它解决什么问题**："给出关系模式，判定范式级别并分解"是应用题常客，乱背定义必挂。
- **核心逻辑**：
  1. 找码 → 码之外的属性全是非主属性。
  2. 非主属性对码有**部分**依赖 → 卡在 1NF，拆完升 2NF（1 拆原子，2 拆部分）。
  3. 还有**传递**依赖 → 卡在 2NF，断传递升 3NF（3 断传递）。
  4. 决定因素不都含码 → 不是 BCNF（BC 管主属性）。
  5. 出现多值依赖 → 4NF 斩多值。
  - 分解=规范化="单一化"：一个关系表示一事或一物。
- **书中用法**：学生(学号,…,系名,系宿舍楼)：学号→系名→系宿舍楼是传递依赖 → 分解出宿舍楼(系名,系宿舍楼)，升到 3NF。
- **书中对照**：合一表之祸——学生-选课-课程合成一张表后：新课没人选、学号空 → 实体完整性拒绝插入（插入异常）；删光某生选课 → 学生信息跟着消失（删除异常）；改姓名只改到一半（修改异常）。拆成三表全消，代价是跨表连接开销。
- **何时失效**：函数依赖靠语义判不靠算——允许重名的表里"姓名→年龄"就是塌的，别按数据当前没有重复来下结论。

→ 深入请读 D1-关系模型与完整性\SKILL.md

### 方法论 4：三级模式与两级映像

- **它解决什么问题**：填空"三级模式各是什么"、判断"哪个映像保哪种独立性"。
- **核心逻辑**：
  - 外模式（=子模式=用户模式，可多个）；模式（=逻辑模式，仅一个）；内模式（=存储模式，仅一个）。
  - 外模式/模式映像保**逻辑**独立性；模式/内模式映像保**物理**独立性。
  - 口诀：映像夹住的两层变了、上层不动 = 独立。
  - E-R 转主键口诀：1:1 随便放，1:n 放 n 端，m:n 组合上（m:n 必须独立成表、键=两端键的组合）。
- **书中用法**：学生-课程是 m:n → 选课表键=(学号,课程号)；课程-教材是 1:1 → 可并入任一端。
- **何时失效**：年代与事件线（人工管理→文件系统→数据库系统）只考填空不考机制——背名字不背故事。

→ 深入请读 D1-关系模型与完整性\SKILL.md

## 二、结构与建库：先有文件再有行（D2）

### 方法论 1：文件三兄弟与页 8060 算账法

- **它解决什么问题**：填空问"主数据文件扩展名"、计算题问"20000 行每行 5000B 要多少空间"——都是同一套账。
- **核心逻辑**：
  - mdf 主数据文件有且只有一个；ndf 次要数据文件 0~n 个；ldf 事务日志至少 1 个。
  - ldf 三条硬规矩：不属于任何文件组、数据与日志不同文件、一个文件只属一个库。
  - 一页 8KB = 8060B 数据 + 132B 系统；行不许跨页 → 每行 ≤8060B。
  - 算式链：每页装几行 = 8060÷行字节（取整）→ 页数 = 行数÷每页行数 → 空间 = 页数×8KB。
- **书中用法**：20000 行×5000B：一页只装 1 行 → 20000 页 → 约 156MB，浪费约 58MB。
- **何时失效**：行里含 text/image 等大对象时不按此账算——教材口径只考"超 8060B 插入失败"这一刀。

→ 深入请读 D2-SQL-DDL数据类型\SKILL.md

### 方法论 2：类型选型四判据

- **它解决什么问题**："13 位学号定义为什么类型""余额用什么"这类说理由的选择题，以及建表题的扣分重灾区。
- **核心逻辑**：
  1. **定变**：定长代码选 char；长短不一选 varchar（多付 2B 管理费换空间弹性）。
  2. **中英**：纯英文数字 char 系（上限 8000）；含汉字选 n 系（上限 4000，每字符双倍空间）。
  3. **大小**：tinyint 1B → smallint 2B → int 4B → bigint 8B，范围翻着长。
  4. **算不算**：不做算术的数字串永远选 char——学号、电话、身份证；精确小数 decimal(p,s)；金额 money 不是 float；开关量 bit 只认 0/1/NULL。
- **书中用法**：上机卡表——上机号 char(13) 主键、余额 money、备注 varchar(50)。
- **何时失效**：类型对了还会死于参数细节——decimal(6,2) 是总 6 位含小数 2 位，写成 decimal(2,6) 直接错。

→ 深入请读 D2-SQL-DDL数据类型\SKILL.md

### 方法论 3：DDL 三板斧与缺省智慧

- **它解决什么问题**：ALTER/DROP 改表改库题，与"判断题六连坑"（日志文件入组、mdf 可多个、IDENTITY 手工塞值……）。
- **核心逻辑**：
  - 表三板斧：`ALTER COLUMN 列 新类型`（只能一列一列改、不能改列名）/ `ADD 列 类型`（可多个）/ `DROP COLUMN 列`。
  - 库另一套：ADD FILE / ADD LOG FILE / REMOVE FILE / MODIFY FILE——MODIFY FILE 只能改大不能改小，改小是 DBCC SHRINK 的活。
  - IDENTITY 自动手：一表一个、不许插值、不许更新、不能绑 DEFAULT。
  - 系统库四兄弟：master 管家、model 模板、tempdb 草稿、msdb 闹钟——不写 USE 默认连 master，在管家头上动土最危险。
  - 建库五件套：逻辑名 NAME、物理路径 FILENAME、初始量 SIZE、天花板 MAXSIZE、长速 FILEGROWTH——数据挂 ON PRIMARY、日志挂 LOG ON。
  - 附加库是 CREATE DATABASE 的隐藏第四用法：`FOR ATTACH`；备份/恢复细节归容灾单元，D2 只留这一句。
  - 默认增长速度：数据文件 1MB、日志文件 10%——"数据要个整数，日志按百分比飘"。
  - 缺省智慧：题目没给路径和 SIZE，`CREATE DATABASE 库名` 最小骨架就收笔。
- **书中用法**：`ALTER TABLE 学生 ALTER COLUMN 家庭住址 varchar(50)`。
- **何时失效**：删正在连接使用中的库会失败；系统数据库永远不能删——这两条不在语法层，在"前提层"。

→ 深入请读 D2-SQL-DDL数据类型\SKILL.md

### 方法论 4：建表题填空式五步模板

- **它解决什么问题**：拿到"根据业务场景写 CREATE TABLE"就发慌——需要一套默写骨架再填空的流程。
- **核心逻辑**：
  1. 定骨架：建库 = CREATE DATABASE 库名 ON PRIMARY(…) LOG ON(…)；建表 = CREATE TABLE 表名(列定义…)。
  2. 填列：每列按"列名 类型(长度) [NOT NULL] [约束]"四格填。
  3. 填文件：建库时每文件括号内五件套 NAME/FILENAME/SIZE/MAXSIZE/FILEGROWTH。
  4. 查漏：有主键吗？外键引用的列在主表里是主键吗？汉字列用 n 系了吗？
  5. 收尾：语句间英文逗号，最后 GO。
- **书中用法**：`CREATE TABLE 专业(专业代码 char(4) CONSTRAINT pk_zydm PRIMARY KEY, 专业名称 varchar(20) NOT NULL, 系部代码 char(2))`。
- **何时失效**：判停——题给全长度与空否就照抄、不自行"优化"类型；题目没给约束名可省 CONSTRAINT 名，写了不加分不扣分。

→ 深入请读 D2-SQL-DDL数据类型\SKILL.md

## 三、查询命门：执行顺序是全卷裁判（D3/D4）

### 方法论 1：书写顺序 vs 执行顺序六拍

- **它解决什么问题**：所有"为什么这个子句里不能用别名""哪里能放聚合"的问题，根源都是执行顺序。
- **核心逻辑**：
  - 书写顺序（目录页）：SELECT→FROM→WHERE→GROUP BY→HAVING→ORDER BY。
  - 执行顺序（施工）：FROM→WHERE→GROUP BY→HAVING→SELECT→ORDER BY。
  - 推论一：WHERE 先于 SELECT → WHERE 用不了列别名。
  - 推论二：ORDER BY 最后执行 → 唯一能放心用别名的出口。
  - 推论三：投影（SELECT）对应 π 自动去重，SQL 必须显式 DISTINCT；选择（WHERE）对应 σ。
- **书中用法**：`WHERE 2024-YEAR(出生日期)>=18`——想用"年龄"这个别名？WHERE 阶段它还没造出来。
- **何时失效**：部分考纲容忍 HAVING 用别名，但考试以聚合表达式（`HAVING COUNT(*)>=4`）为准最稳。

→ 深入请读 D3-单表查询\SKILL.md

### 方法论 2：三层筛子——WHERE 筛行、GROUP 切组、HAVING 卡阻

- **它解决什么问题**：分组查询的两大错——聚合条件塞进 WHERE、行级条件误进 HAVING。
- **核心逻辑**：
  - WHERE 是门卫（进门查每个行），HAVING 是评委（分组演出后淘汰整组）。
  - 一条判据走天下：这个条件在切组之前能不能对单独一行判断？能 → WHERE，不能 → HAVING。
  - SELECT 里每个非聚合列必须都在 GROUP BY 清单里——非分组列不许裸奔。
  - 书写骨架：SELECT 列清单 FROM 表 [WHERE 行条件] [GROUP BY 分组列] [HAVING 组条件] [ORDER BY 排序列]。
- **书中用法**：`SELECT 课程号,COUNT(*) AS 选课人数 FROM 课程注册 GROUP BY 课程号 HAVING COUNT(*)>=4`——WHERE 里写 COUNT(*) 直接非法。
- **何时失效**：题目把"成绩>=80"这类行级条件包装成组问题——它仍判得动单行，必须放回 WHERE。

→ 深入请读 D3-单表查询\SKILL.md

### 方法论 3：聚合函数对 NULL 的态度表

- **它解决什么问题**："5 个成绩 1 个 NULL，COUNT(*)/COUNT(成绩)/AVG(成绩) 各是多少"——填空判断双料高频。
- **核心逻辑**：
  - 只有 COUNT(*) 计入含 NULL 的行；COUNT(列)/SUM/AVG/MAX/MIN 全部跳过 NULL。
  - 出题公式：某列 k 个 NULL → COUNT(*) 与 COUNT(列) 相差 k；AVG 分母因此比行数小。
  - 判空唯一写法 IS NULL——等号进不去 NULL 的门。
  - WHERE 六类谓词弹药：比较（<>、!= 同义；!< 即 >=）、BETWEEN 含两端、IN 等价一串 OR、LIKE 配 % _ [ ] [^ ]、IS NULL、AND/OR/NOT（AND 高于 OR）。
  - LIKE 细则：% 随便多长、_ 只站一位；含 %/_ 的字面串要 ESCAPE 转义，且只转义紧跟一个字符。
  - BETWEEN 端点判断：BETWEEN 80 AND 89 含 89；题干"[80,89)"必须拆成 >=80 AND <89。
  - TOP n 不配 ORDER BY 时"前 n 条"无意义——表的自然序不保证；INTO 造副本配 `WHERE 1=2` 只复制结构。
  - 集合算子补记：UNION 自动去重、UNION ALL 留客；INTERSECT 找共同，EXCEPT 有方向（R−S ≠ S−R）。
- **书中用法**：5 行成绩含 1 个 NULL：COUNT(*)=5，COUNT(成绩)=4，AVG 分母 4。
- **何时失效**：空集坑反方向——SUM/AVG 空集返回 NULL 不是 0，只有 COUNT 空表返回 0；把"空表求和=0"答出去就是丢分。

→ 深入请读 D3-单表查询\SKILL.md（NULL 态度细则另见 D6）

### 方法论 4：外连接方向决定保留谁，谱系收住全家

- **它解决什么问题**："LEFT JOIN 结果多少行"的计算题、"无成绩学生要不要出现在结果里"的设计题、等值 vs 自然连接的辨析题。
- **核心逻辑**：
  - 内连接 = 只留配上的；外连接 = 保留没配上的，缺的那侧补 NULL。
  - LEFT JOIN 左表全保留；RIGHT 换方向；FULL 两边都保——方向只看 JOIN 左边是谁。
  - 行数公式：结果行 = 配上的行数（按连接字段值逐值配对相加）+ 保留侧没配上的行数。
  - 笛卡儿积另算账：行相乘、列相加。
  - 谱系：θ连接 ⊃ 等值连接 ⊃ 自然连接（再去掉重复列）——等值连接只从行挑，自然连接从行和列两个角度运算。
  - 自身连接必须给同一张表起两个别名（first/second）；多表同名列必须表名前缀。
- **书中用法**：学生 4 行 5 列 × 专业 3 行 3 列 → 交叉连接 16 行 8 列；LEFT JOIN 保留 6 名无成绩学生、成绩列填 NULL；自身连接口径 `first.专业代码<>second.专业代码`。
- **书中对照**：ODBC 四层按职责分——应用（说话的）→ 驱动程序管理器（派活的，管加载/检查参数/单一入口）→ DBMS 驱动（干活的，管连接/提交 SQL/错误码转换）→ 数据源 DSN（存货的，只是命名的桥梁不是数据库）；ASP 里 ADO 三成员 connection/command/recordset。
- **何时失效**：INNER 关键字可省——写 JOIN 默认就是内连接，别把省略误读成外连接；连接与子查询"某些可互换某些不能"的细节不归本单元收，括号里藏 SELECT 一律移交函数与子查询域。

→ 深入请读 D4-连接与多表\SKILL.md

## 四、优化与抽象：不存数据，只改效率与视野（D5）

### 方法论 1：索引 = 书的目录，聚集 = 书柜排好序

- **它解决什么问题**：简答"索引的意义/建立要考虑什么"、判断"索引越多越好""一表可建多个聚集索引"。
- **核心逻辑**：
  - 索引 = B 树排序结构，避免全表扫描（全表扫描=逐页翻书，走索引=先查页码再直翻）。
  - 代价三段：占空间（聚集≈1.2×数据量）、创建维护耗时、更新变慢。
  - 聚集索引：物理顺序=索引顺序、叶层即数据页、**一表一个**（默认主键自动建）。
  - 非聚集索引叶层是行定位器；**一表最多 249 个**；默认创建的就是它。
  - 原则链：主键必建 → 外键可建 → 常查列好建；重复值多/text/bit 列不建；常更新表忌多索引、小表建了白亏。
  - 维护词条：碎片检查 DBCC SHOWCONTIG（扫描密度理想 100%）、整理 DBCC INDEXDEFRAG；查索引信息 EXEC sp_helpindex 表名。
- **书中用法**：`CREATE UNIQUE CLUSTERED INDEX jxkc_zy_index ON 教学计划(课程号,专业代码)`。
- **何时失效**：报表表（只查不改）可以多建，流水表（高频 INSERT/UPDATE）多建索引是赔本买卖——"越多越好"只在判断题里是错的。

→ 深入请读 D5-索引与视图\SKILL.md

### 方法论 2：视图 = 窗户，更新要能唯一还原回一张基表

- **它解决什么问题**：视图简答定性题、操作题里"通过视图能不能更新"的判据题。
- **核心逻辑**：
  - 定性：虚拟表，库里只存 SELECT 定义，查询时视图消解、一切操作转回基表。
  - 优点四点：简化操作、多角度看同一数据、逻辑独立性、安全保护。
  - 更新判据一句话：这次修改能否唯一还原为某**一张**基表上的某一行？——一条语句只能动一个基表。
  - WITH CHECK OPTION：修改不许把行改出"围栏"（成绩≥60 的视图改不到 50）。
  - 三类视图：标准视图 / 索引视图（SCHEMABINDING + 唯一聚集索引才物化存储、查询提速）/ 分区视图（跨服务器 UNION）。
  - 数字钩：嵌套视图 ≤32 层、一视图 ≤1024 列、复合索引 ≤16 列且 ≤900B。
- **书中用法**：view2（学生 JOIN 系部）上 `UPDATE view2 SET 姓名='王洪' WHERE 学号='…'` 可以——只落一张基表；同一句再改系部名称就报错。
- **何时失效**：连接+筛选视图 INSERT 直接拒绝——无法唯一映射回任何一张基表的完整行；基表删除后视图不自动消失，需手动 DROP VIEW。

## 五、函数速查：返回值帧就是答案（D6）

### 方法论 1：函数题统一判据——输入啥→返回啥，外加 NULL 怎么办

- **它解决什么问题**：填空题直接给函数调用填返回值，选择题比函数差异——没有方法论就是死记。
- **核心逻辑**：
  - 四类同法：认类（聚合/字符串/日期/数学/转换）→ 问 NULL（参数里混 NULL 会怎样）→ 对返回类型（int 还是字符串）。
  - 锚定四句：聚合怕 NULL、字符串怕空格、日期分 int/串、转换怕失败。
  - 关键帧：COUNT(*) 含 NULL 行；CONCAT 把 NULL 当空串；YEAR/MONTH/DAY 返回 int；TRY_CONVERT 失败返 NULL 不报错。
  - key 帧：CHARINDEX 找不到=0（>0 即命中）；CHOOSE(3,'A','B','C','D')→'C'（1 起数）；IIF(3>2,'T','F')→'T'。
- **书中用法**：`CONCAT('hello',NULL,'world')` → helloworld；但 `'hello'+NULL+'world'` 的 + 拼接遇 NULL → NULL。
- **何时失效**：降级词条（@@VERSION、COL_LENGTH、RANK/ROW_NUMBER）只认名字不出帧——考到样子不考返回值。

→ 深入请读 D6-内置函数\SKILL.md

### 方法论 2：取整方向与三对"双胞胎"

- **它解决什么问题**：CEILING/FLOOR/ROUND 返回值、CHARINDEX vs PATINDEX、CAST vs CONVERT 这类对比题。
- **核心逻辑**：
  - CEILING 向大、FLOOR 向小，负数不反转：CEILING(-56.3)→-56，FLOOR(-56.3)→-57。
  - ROUND(x,y)：y 负 = 小数点左侧取整，ROUND(56.34,-1)→60。
  - 三对双胞胎：CHARINDEX 找不到 = 0 而 PATINDEX 支持通配符；CAST 无 style 而 CONVERT 多 style 管日期格式；CONVERT 失败报错而 TRY_CONVERT 兜底 NULL。
  - LEN 不计尾随空格：LEN('abc ')→3。
- **书中用法**：`CHARINDEX('雪',姓名)>0` 即"姓名含雪"命中；`PATINDEX('%tt%','wwttyy')` → 3。
- **书中对照**：`CAST('123' AS int)+20` → 143；`TRY_CONVERT(float,'ttt')` → NULL 不报错。
- **何时失效**：位置从 1 而不是 0 起——SUBSTRING(str,start,len) 记"位置+长度"两个参数，从 0 取会出头。

→ 深入请读 D6-内置函数\SKILL.md

### 方法论 3：日期族三件套

- **它解决什么问题**：填空考日期函数返回值，坑全在"返回类型"与"月末"。
- **核心逻辑**：
  - YEAR/MONTH/DAY 返回 int；DATENAME(part,d) 返回字符串（weekday→'星期二'）。
  - GETDATE() 返回 datetime 带毫秒；DATEFROMPARTS(y,m,d) 拼日期。
  - EOMONTH(d[,n])：所在月（+n 月）最后一天。
- **书中用法**：`EOMONTH('2017-01-16',1)` → '2017-02-28'——下个月的月末。
- **何时失效**：教材把用户定义函数（§8.2~8.4）混排在内置函数章——题面问"内置"时不答用户定义函数。

## 六、编程与事务：要么全做，要么全不做（D7）

### 方法论 1：ACID 四钩与 @@TRANCOUNT 双口径

- **它解决什么问题**："事务哪四性、各起因于什么"是简答必考；ROLLBACK 后 @@TRANCOUNT 变不变是判断坑。
- **核心逻辑**：
  - 四钩：原子性（全做或全不做）、一致性（账目不坏）、隔离性（排队不串）、持久性（停电不丢）。
  - 起因对应：多操作捆绑 / 状态守恒 / 并发互控 / 扛系统故障。
  - 显式事务 BEGIN TRAN / COMMIT / ROLLBACK；SAVE TRAN 设保存点——同名重用时旧保存点失效。
  - @@ERROR 只记最后一条语句的错误码——判错必须紧跟出错语句。
  - @@TRANCOUNT 双口径：回滚到事务开始点减 1；只回滚到保存点不变。
  - 隐式事务清单点名：一条 INSERT/DELETE/UPDATE/SELECT/CREATE/ALTER/DROP/TRUNCATE TABLE/GRANT/REVOKE 即一个事务。
  - 事务名 ≤32 字符、局部变量名 ≤128 字符——数字钩别背混。
- **书中用法**：`IF @@ERROR<>0 ROLLBACK TRAN ST ELSE COMMIT TRAN`。
- **何时失效**：TRUNCATE TABLE 不记日志、不触发 DELETE 触发器——"删全表"出题按 TRUNCATE 口径判，不是 DELETE。

→ 深入请读 D7-事务与TSQL编程\SKILL.md

### 方法论 2：请饭与保安——存储过程 / 触发器辨析

- **它解决什么问题**：简答两大必考（两者异同）+ 骨架填空（CREATE PROC、CREATE TRIGGER）。
- **核心逻辑**：
  - 存储过程是"请饭"：用户 EXEC 点名才上菜，可收参数——OUTPUT 形参实参都要加 OUTPUT。
  - 触发器是"保安"：不能 EXEC 调用、不许带参数、绑在表上数据变动自动激发。
  - AFTER/FOR = 事件成功后补动作；INSTEAD OF = 取消原语句以动作替代。
  - 虚表三拍：INSERT 读 inserted、DELETE 读 deleted、UPDATE 旧进 deleted 新进 inserted；限定列用 `IF UPDATE(列)`（删除不能用）。
  - 违约处理标配：`PRINT 提示 + ROLLBACK TRANSACTION`。
  - 四动词配套：CREATE / ALTER / DROP / EXEC；查文本 sp_helptext、一般信息 sp_help、相关性 sp_depends。
  - 维护完整性时外键约束优先于触发器——教材例即以 INSTEAD OF DELETE 化解级联冲突。
- **书中用法**：`CREATE TRIGGER SafetyXS ON DATABASE FOR DROP_TABLE,ALTER_TABLE AS PRINT('禁止…') ROLLBACK TRANSACTION`——DDL 触发器守表结构。
- **何时失效**：CREATE TRIGGER 必须是批处理第一条语句，不能建在临时表/系统表上；数字别对调——嵌套默认允许上限 32 层、递归默认禁用最多 16 层。

→ 深入请读 D7-事务与TSQL编程\SKILL.md

### 方法论 3：批处理红线与变量双赋值

- **它解决什么问题**：GO 到底算不算语句、SELECT 和 SET 谁一条能赋几个变量——判断题常客。
- **核心逻辑**：
  - GO 是批结束标记，不是 T-SQL 语句——服务器收到的批不含 GO。
  - 语法错误整批不能编译；执行错误只终止出错处到批尾。
  - 赋值规则：SELECT 一条可赋多个变量；SET 一条只赋一个；SELECT 回多值时变量取最后一个。
  - 局部变量 @ 批一结束就消亡，不能跨批引用。
  - 输出通道：PRINT 走"消息"窗格，SELECT 走"结果"窗格——考试常以此辨析两条输出路径。
- **书中用法**：`DECLARE @s char(2)` 换行 `SET @s='01'`——改成一条 SET 赋两个变量则非法。
- **何时失效**：多行注释不能跨越批处理——注释撞上 GO 就断，别把块注释写成跨界长条。

### 方法论 4：锁三兄弟与死锁三步走

- **它解决什么问题**：隔离性的追问题——共享锁/排他锁怎么共存、死锁怎么防怎么解。
- **核心逻辑**：
  - 锁粒度从小到大：行/页/扩展盘区/表/数据库；小粒度高并发但开销大，升级按 2% 标准。
  - 共享 S 锁：SELECT 用、可多把共存；排他 X 锁：INSERT/DELETE/UPDATE 用、唯一；更新锁：UPDATE 两阶段升格。
  - 死锁三步：预防=一次封锁/顺序封锁；诊断=超时设置/等待图找回路；解除=选最小代价牺牲者回滚并恢复其已做修改。
- **书中用法**：口答题直接落三步走框架——"如何预防、如何诊断、如何解除死锁"各答一条。
- **何时失效**：教材本单元只给机制级一句话带过——考深细节（锁兼容矩阵）不背，按三步走框架收口。

### 方法论 1：两级门禁与权限账本三动词

- **它解决什么问题**：授权应用题（"只允许某用户读某表"）与"三种权限冲突谁起作用"的填空。
- **核心逻辑**：
  - 两级门禁：登录名=大门钥匙（服务器层，管能不能连上）；数据库用户=房间通行证（由登录名映射，管进哪个库）；权限=房间里能碰哪张桌子。
  - 验证模式判据一句话：是否放行 SQL Server 独立登录账号——能用 SQL Server 身份验证登录 = 混合模式；非 Windows 用户要连库必须混合模式。
  - 有钥匙没通行证：连得上服务器、打不开数据库——登录名 ≠ 能做插入更新。
  - 权限账本：GRANT 记一笔"允许"；REVOKE 把这笔划掉（回中立，还能再存）；DENY 盖"冻结"章。
  - 一票否决：多个来源 GRANT 中只要有一个 DENY → 拒绝。
  - REVOKE 后可通过加入角色重新获得允许；DENY 后永远不能。
- **书中用法**：`GRANT SELECT ON 学生 TO stu`——建登录名→映射用户→建角色授 SELECT→入角色。
- **何时失效**：改验证模式（Windows/混合）后必须重启 SQL Server 服务才生效——只写"改属性"不给满。

→ 深入请读 D8-安全管理\SKILL.md

### 方法论 2：角色是权限的标准容器

- **它解决什么问题**：填空选择考角色数量与 public/sa；应用题里"用户多时怎么授权"的方法论。
- **核心逻辑**：
  - 服务器角色 9 个管"楼"（配给登录名）：sysadmin 全权限、dbcreator 建库、securityadmin 管登录……
  - 固定数据库角色 10 个管"房间"（配给用户）：db_owner 全权、db_datareader 只读、db_ddladmin 可发 DDL 但不能发 GRANT/REVOKE/DENY。
  - 两个预置黑名单：db_denydatareader / db_denydatawriter——"不能读/不能改任何数据"。
  - 权限三分类：对象权限（表/视图的 SELECT/INSERT/UPDATE/DELETE、存储过程的 EXECUTE）、语句权限（CREATE TABLE、BACKUP DATABASE 等）、隐含权限（sysadmin/dbo 自带、无需授予不可设置）。
  - public 人人必有、新用户自动加入；sa 装完密码为空，第一件事设密码。
  - 继承三句：用户继承所属角色权限；多角色基本取并集；只要有一个来源 DENY 即拒绝。
  - 权限挂角色不挂用户——用户删了角色随库长存，权限不跟着消失。
- **书中用法**：role_stu 角色授"学生"表 SELECT，stu 入角色即只读。
- **何时失效**：应用程序角色本身不含任何成员——是"以程序身份接替用户"的特例，别把它按普通角色算成员资格。

### 方法论 3：备份四类型与摄影四兄弟

- **它解决什么问题**：填空简答"备份有哪几种/增量备份指什么"、选择问各备份适合什么库。
- **核心逻辑**：
  - 完整 = 全家福（所有数据+对象，慢而大，链条底座，只能到备份时刻）。
  - 差异 = 只拍新来的（基准 = 最近一次完整备份，快，不能到失败点）。
  - 事务日志 = 监控录像（记录动作，按序重放可到失败点，最小最快）。
  - 文件/文件组 = 按房间拍（只备局部，还原快，但必须再配日志备份）。
  - 三层节拍：完整每晚 → 差异 3~4 小时 → 日志 10~30 分钟。
  - 系统库口规：master/msdb/model 定期备份；tempdb 不可备份（启动重建、关闭清空）。
  - 备份期间四禁：建删数据库文件、建索引、非日志操作、收缩数据库。
- **书中用法**：`BACKUP DATABASE student TO studentbak`（差异加 WITH DIFFERENTIAL）。
- **何时失效**：教材"批日志还原性能优于简单/完全还原"的收录口径是"减少批操作日志空间"——优势仅此一项，别写成全方位优越。

→ 深入请读 D9-备份还原与导入导出\SKILL.md

### 方法论 4：还原链条铁律与日志尾抢拍

- **它解决什么问题**："崩溃后第一步做什么"是选择高频；带时间表的应用题漏一步丢一路分。
- **核心逻辑**：
  - 放映铁律：先放最近一张全家福（完整）→ 最近一份差异 → 按时间顺序连放日志，一环不跳。
  - 最易漏的一步：日志可访问时，第一步不是还原完整备份，而是**先备份当前活动事务日志（日志尾）**。
  - 抢不到日志尾 → 只能回到最后一次日志备份状态，到不了失败点。
  - 判停条件：题面只问"备份类型/恢复方式哪几种"→ 答类型即停；给了具体时间表 → 必须走满还原序列并逐一点名时间点，漏点时间 = 丢步骤分。
  - 恢复模式承诺能力：简单 = 完整+差异（回不到失败点）；完全 = 完整+差异+日志（几乎不丢数据）；批日志配方同完全。
  - 两个"事务日志"不是一回事：D9 里它是被备份的对象，D7 里它是 ACID 的底层机制——考到先分单元口径。
  - 三对易混：完整 vs 差异 = 变化基准；差异 vs 日志 = 状态快照差 vs 动作流；恢复模式 vs 备份类型 = 能力承诺 vs 原材料。
  - 语法帧：`BACKUP DATABASE student TO studentbak` / `RESTORE DATABASE student FROM studentbak`；日志备份用 BACKUP LOG，还原用 RESTORE LOG … WITH NORECOVERY（链未完）/ WITH RECOVERY（收尾）。
- **书中用法**：周日 0:00 完整备份 → 崩溃时：抢日志尾 → 还原最近完整 → 最近差异 → 依序日志。
- **何时失效**：导入导出是另一条线——备份是自救（.bak 只能被 RESTORE 读），导入导出是外交（.xls 谁都能读），别用"复制文件"回答备份题。

## 陷阱与反例

以下六条由九个单元的 B 边界/失效段中挑选，从六个层面对“逻辑自洽却判错”的重灾区进行了梳理。
交卷前用节末的自检清单做最后一遍回扫——这六条中的任何一条都能让一整道大题归零。

### 陷阱 1：LEFT JOIN 后 WHERE 过滤保留侧补 NULL 列 → 外连接退化成内连接

- **陷阱**：建好 `学生 LEFT JOIN 成绩` 想保留无成绩学生，又在 WHERE 里补一句 `WHERE 成绩>=60`——无成绩学生的补 NULL 成绩被条件筛掉，孤儿学生整体出局，LEFT JOIN 白写了。
- **为何掉进去**：普通查询里"过滤条件放 WHERE"是肌肉记忆；外连接下 WHERE 已晚于补 NULL，`成绩>=60` 对 NULL 行判定为 UNKNOWN（非 TRUE），整行被剔。
- **预警信号**：题干要"保留所有 X（含没配上的）"+ WHERE 里出现非保留侧的列条件——条件会筛掉补 NULL 的保留行，就挪进 ON。
- **同族反例**：教材例 5.34 把成绩条件放进 ON 的内连接语境合法——位置对错取决于连接类型，勿照搬。

### 陷阱 2：聚合条件写进 WHERE（`WHERE COUNT(*)>=4`）

- **陷阱**：分组统计"选课人数 4 人以上"，把 `COUNT(*)>=4` 塞进 WHERE——直接非法。
- **为何掉进去**：WHERE 和 HAVING 看起来都是"筛选"，考生没意识到 WHERE 在 GROUP BY **之前**执行——那一刻组还不存在，COUNT 无处安放。
- **预警信号**：条件里任何聚合函数出现在 WHERE → 一票否决挪 HAVING；反过来行级条件（成绩>=80）进了 HAVING → 回 WHERE。判据：切组之前能否对单行判断。
- **同族反例**：教材例 5.22 的变式陷阱——把"人数≥4"改成"成绩>=80"后答案要反向搬家，同一道题两种放法。

### 陷阱 3：`= NULL` 判空

- **陷阱**：写 `WHERE 备注=NULL` 查"备注为空的教师"——语法放行，结果永远为空。
- **为何掉进去**：直觉上"等于空"是自然语言；但 NULL 代表"未知"，任何与 NULL 的等值比较都是 UNKNOWN 进不了 WHERE 的门。
- **预警信号**：判空唯一写法 IS NULL / IS NOT NULL；`=` `<>` `!=` 撞上 NULL 一律判错——教材明文：IS 运算符不能用 '=' 代替。
- **同族反例**：NULL ≠ 0 ≠ 空格，三者互不相同——"NULL 就是 0"类判断题答案是错。

### 陷阱 4：DENY 一票否决穿不透

- **陷阱**：用户属于 10 个角色、9 个 GRANT，以为并集全绿——但只要一个来源有 DENY，访问被拒。
- **为何掉进去**：把权限想成"多角色投票多数决"；实际是"拒绝优先"的冻结章逻辑——DENY 之后无论什么来源补多少 GRANT 都救不回来（这是与 REVOKE 的本质区别）。
- **预警信号**：继承规则三句——用户继承角色权限、多角色基本取并集、但"只要有一个 DENY 即被拒绝"；看到多角色来源先扫 DENY。
- **同族反例**：判断题"取消权限后无法通过角色重新获得"是错——那是 DENY 的属性；REVOKE 划掉一笔，DENY 冻结整个账户。

### 陷阱 5：多表连接视图随便 UPDATE

- **陷阱**：在学生 JOIN 系部的视图上一条语句同时改"姓名"和"系部名称"，或在连接+筛选视图上直接 INSERT——报错。
- **为何掉进去**：定性时知道"视图操作转回基表"，却忘了转回受限：一条 UPDATE/INSERT 只能落**一个**基表，且候选基表必须能拼出该行的完整值。
- **预警信号**：判据——这次修改能否唯一还原为某一张基表上的某一行？跨两表改值、INSERT 缺基表非空列都会被整体回绝；WITH CHECK OPTION 再加一道围栏。
- **同族反例**：判断题"基本表删除后视图还能查"为错（消解无源可转）——但"删基表会自动删视图"也是错，需手动 DROP VIEW。

### 陷阱 6：ROLLBACK 双口径与空表 SUM 谜

- **陷阱**：a．只回滚到保存点时 @@TRANCOUNT 不变，答"减 1"就错；b．空表 `SUM(成绩)` 返回 NULL 不是 0。
- **为何掉进去**：把"回滚 = 计数归零"当直觉，忘了"回滚到事务开始点减 1、回滚到保存点不变"的分界；SUM/AVG"看不见 NULL 于是当 0"更是把两种规则搅在了一起。
- **预警信号**：SAVE TRAN 出现 → 画两条回滚线分别算 TRANCOUNT；聚合遇到空集 → 只有 COUNT 会给 0，SUM/AVG 给 NULL。
- **同族反例**：SUM/AVG 空集返 NULL 属 SQL 标准行为、教材未明说——答"空表求和=0"正是出题人设的口袋。

## 教材的局限（考试口径随行）

以下四条从各单元 verified.md 的"教材存疑点"汇总——应试时按口径答，实操时勿照搬。

1. **版本能力表述失真（D8/D9）**：教材称"任何用户一般都具有表或视图的读权限"（public 实际不默认授 SELECT）、"导入导出只在企业版/开发版且须装 SP1"、"2012 只支持备份到本地磁带机"——均与 SQL Server 实际不符。**考试口径：按教材表述作答，实操勿照搬。**

## 关键术语速查

挑 15 条最高频——填空/名词解释/判断题直取。判据必须是"一眼可判"的形态，长解释去原单元查。

| 术语 | 一句话判据 |
|---|---|
| 主键 | 唯一+非空；行行有身份证 |
| UNIQUE | 列内不重复但**允许空值**——与主键的唯一分界线 |
| 外键 | 不是本表主键，指向别表的主键/候选键 |
| CHECK | 布尔划红线，一字段可挂多个（规则只能一个） |
| IDENTITY | 自动手：一表一个、不喂饭、不许改 |
| 范式 | 1 拆原子，2 拆部分，3 断传递，BC 管主属性 |
| 三级模式 | 外看、中管、内存；外/模式映像保逻辑独立 |
| 五子句执行序 | FROM→WHERE→GROUP BY→HAVING→SELECT→ORDER BY |
| HAVING | 筛"组"：条件里含聚合或分组列才合法 |
| 聚合函数与 NULL | 除 COUNT(*) 全部跳过 NULL；AVG 分母因此变小 |
| IS NULL | 判空唯一门禁，等号进不去 |
| 自然连接 | 等值连接再去掉重复列（行列两个角度） |
| 聚集索引 | 物理顺序=索引顺序、叶层即数据页、一表一个 |
| 视图 | 虚拟表，只存 SELECT 定义、操作转回基表 |
| 事务 ACID | 全做或全不做 / 账目不坏 / 排队不串 / 停电不丢 |
